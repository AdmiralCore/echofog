# Нода протокола v2 на VPS

Здесь описана установка серверной ноды EchoFog v2 (ретранслятор, почтовый ящик, при желании выход) на
арендованный Linux-сервер. Прежнее руководство для протокола v1 — [deploy-vps.ru.md](deploy-vps.ru.md).
Все адреса ниже — заглушки из документационных диапазонов: `203.0.113.10` означает публичный IP-адрес
сервера.

## 1. Что нужно

- Linux-сервер (Ubuntu 22.04 и новее, Debian 12 и новее) с публичным IPv4- или IPv6-адресом и доступом root.
- Один UDP-порт, доступный из интернета. По умолчанию 443: он сливается с трафиком HTTP/3.
- По желанию — домен, DNS которого указывает на сервер (для собственной обложки ноды). Без домена нода
  работает только для своих: публичной карточки у неё нет.
- Нода обслуживает **только UDP** (носитель noise3). TCP-порты остаются закрытыми.

## 2. Установка через Docker

Образ собирается из `deploy/v2/Dockerfile` и работает от непривилегированного пользователя, с файловой
системой только для чтения и без привилегий.

```
cp deploy/v2/.env.example deploy/v2/.env      # затем отредактировать: ECHOFOG_ADVERTISE_ADDR=203.0.113.10
docker compose -f deploy/v2/docker-compose.yml --env-file deploy/v2/.env up -d
```

`ECHOFOG_ADVERTISE_ADDR` обязателен при первом запуске и должен быть IP-литералом. Без него контейнер не
стартует. Роли задаются в `ECHOFOG_ROLES`; пустое значение выключает все роли.

## 3. Установка без Docker

`deploy/v2/install.sh` скачивает бинарь и подписанный манифест релиза по https и запускает собственный
установщик ноды. **Бинарь проверяется до установки**: установщик сверяет его с манифестом (две подписи из
трёх ключей релиза, вшитых в сборку) и не пишет файлов и не выполняет системных команд, пока проверка не
пройдена. Скрипт нужно скачать, прочитать и запустить от root. Передавать скачанное в оболочку по конвейеру
нельзя.

```
ECHOFOG_RELEASE_URL=https://example.org/releases/v2 sh install.sh --preset relay --advertise 203.0.113.10 --lang ru
```

Установщик создаёт системного пользователя `echofog`, папку данных `/var/lib/echofog` (права 0700),
укреплённый unit systemd и печатает команды для открытия файрвола. Файрвол он не меняет и сервис не
запускает, пока не указан `--start`. Без `--preset` вопросы задаются в терминале (язык, роль, домен, порт,
адрес). Пресеты: `relay`, `exit-free` (отдаёт соединение сервера другим людям: ответственность за этот
трафик остаётся на операторе), `home-entry`. Платный и приватный выход появятся позже.

Запуск: `systemctl enable --now echofog-node`.

**Что эта проверка не покрывает (якорь доверия).** Проверку выполняет сам скачанный бинарь ключами релиза,
вшитыми в него, а скрипт запускает этот бинарь от root до какой-либо проверки. Подписи защищают от
повреждённого файла и от поддельного манифеста рядом с честным бинарём. От того, кто контролирует канал
загрузки и подсунул враждебный бинарь вместе с подходящим манифестом, они **не защищают**: такой бинарь
просто ничего не проверит. Якорь доверия должен прийти извне загрузки: перед запуском нужно сверить
отпечатки ключей релиза с опубликованными на сайте проекта через другой канал или проверить подпись самого
`install.sh`. При сомнениях бинарь можно собрать из исходников и передать самому через `--binary` и
`--manifest`.

## 4. Первый запуск и фраза восстановления

Установщик показывает **фразу восстановления один раз**. Её нужно записать и хранить отдельно от сервера.
В Docker фраза лежит в `recovery-phrase.txt` внутри тома данных (в журнал контейнера она не попадает);
файл нужно скопировать и удалить:

```
docker compose -f deploy/v2/docker-compose.yml exec node cat /data/recovery-phrase.txt
docker compose -f deploy/v2/docker-compose.yml exec node rm /data/recovery-phrase.txt
```

Ключи лежат в папке данных с правами 0600 и не попадают ни в один журнал.

## 5. Проверка доступности

```
echofog-node v2 doctor --data /var/lib/echofog
echofog-node v2 status --data /var/lib/echofog
```

`doctor` проверяет конфигурацию, права на файлы, UDP-порт, подключённых пиров, часы, свободное место на
диске, а также DNS-имя и сертификат обложки. Наружу он ничего не отправляет, пока не указан `--dns`.
Доступность порта снаружи определяется по подключению пира: `status` показывает число сессий. UDP-порт
нужно разрешить в файрволе и в панели хостера:

```
ufw allow 443/udp
```

## 6. Пресеты и файрвол

| Пресет | Что делает |
|---|---|
| relay | ретранслятор, почтовый ящик и DHT для других; выхода нет |
| exit-free | то же и бесплатный выход |
| home-entry | ретранслятор с отдельным портом приглашений, для проводных сетей (мобильным сетям с белыми списками нужен проверенный адрес) |

Порт приглашений (`ECHOFOG_INVITES=true` или пресет `home-entry`) — ещё один UDP-порт: его тоже нужно
открыть. API оператора слушает только `127.0.0.1` и публиковать его нельзя.

## 7. Обновление

`echofog-node v2 update --manifest-url https://example.org/releases/v2/manifest.bin` ищет более новую
версию, спрашивает согласие перед установкой и никогда не возвращает старую версию. В Docker образ
обновляется сменой тега и перезапуском контейнера.

## 8. Если что-то не работает

- `doctor` сообщает, что порт занят: UDP-порт держит другой процесс; его нужно остановить или выбрать другой порт.
- Пиры не подключаются: UDP-порт закрыт файрволом или панелью хостера.
- Часы расходятся: нужно включить синхронизацию времени (`systemd-timesyncd` или `chrony`).
- «Нет публичной карточки»: у ноды нет обложки, она обслуживает только своих. Для обложки нужны домен и
  камуфлированный слушатель, которые появятся в следующих выпусках.
