# Нода протокола v2 на VPS

Здесь описана установка серверной ноды EchoFog v2 (ретранслятор, почтовый ящик, при желании выход) на
арендованный Linux-сервер. Прежнее руководство для протокола v1 — [deploy-vps.ru.md](deploy-vps.ru.md).
Все адреса ниже — заглушки из документационных диапазонов: `203.0.113.10` означает публичный IP-адрес
сервера.

## 1. Что нужно

- Linux-сервер (Ubuntu 22.04 и новее, Debian 12 и новее) с публичным IPv4- или IPv6-адресом и доступом root.
- Один публичный порт, доступный по **TCP и UDP**. По умолчанию 443: он сливается с обычным HTTPS и
  трафиком HTTP/3 — на нём слушают reality2-quic и reality2-tcp, а noise3 переезжает на 444.
- По желанию — домен, DNS которого указывает на сервер, и папка с собственным сайтом оператора (своя
  обложка). С ними незнакомец или зонд на 443 получает настоящий сайт. Без них нода работает только для
  своих: публичной карточки у неё нет.

## 2. Установка через Docker

Образ собирается из `deploy/v2/Dockerfile` и работает от непривилегированного пользователя, с файловой
системой только для чтения и без привилегий.

```
cp deploy/v2/.env.example deploy/v2/.env      # затем отредактировать: ECHOFOG_ADVERTISE_ADDR=203.0.113.10
docker compose -f deploy/v2/docker-compose.yml --env-file deploy/v2/.env up -d
```

`ECHOFOG_ADVERTISE_ADDR` обязателен при первом запуске и должен быть IP-литералом. Без него контейнер не
стартует. Роли задаются в `ECHOFOG_ROLES`; пустое значение выключает все роли.

С обложкой задайте `ECHOFOG_COVER=node.example.org:443` и `ECHOFOG_SITE_DIR` — папку с сайтом оператора
(index.html и остальное). Оба значения нужны вместе: обложка без сайта отклоняется, чужой сайт не
раздаётся. `ECHOFOG_COVER_CERT` — необязательный PEM-файл с цепочкой сертификата домена и его ключом;
пусто означает ACME. `ECHOFOG_ACME_ACCEPT_TOS` (по умолчанию `true`) фиксирует согласие оператора с
условиями центра сертификации; `false` отказывается от ACME и требует сертификат. `ECHOFOG_ACME_EMAIL` —
необязательный контакт. Откройте 443/tcp и 443/udp, а также 444/udp для noise3 — так публикует порты
`deploy/v2/docker-compose.yml`.

## 3. Установка без Docker

`deploy/v2/install.sh` скачивает бинарь по https и запускает собственный установщик ноды. **Корень доверия
это блок публичных ключей релиза внутри `install.sh`.** Скрипт проверяет подписи подписанной записи релиза
(`release.txt`) командой `ssh-keygen -Y verify` (подписать должны два из трёх ключей релиза) и сверяет
размер и SHA-256 бинаря с этой записью. Скачанный файл становится исполняемым и запускается только после
этого; при любой ошибке он удаляется и ничего не устанавливается. Затем установщик ноды ещё раз сверяет
бинарь с подписанным манифестом.

Поэтому вручную нужно проверить одно: что сам `install.sh` подлинный, то есть SHA-256 **всего файла**
совпадает со значением (отпечатком), опубликованным для этого релиза. Передавать скачанное в оболочку по конвейеру
нельзя. Файл нужно скачать, сверить значение и только потом запускать от root:

```
curl --proto '=https' --tlsv1.2 -fsSL -o install.sh https://example.org/install.sh
sha256sum install.sh
```

Выведенное значение должно в точности совпасть с опубликованным на сайте проекта **и** в README
репозитория (два независимых места; при расхождении нужно остановиться). `sha256sum` не исполняет код из
файла. Значение меняется с каждым релизом, потому что порог версии входит в файл: нужно брать то, что
опубликовано для устанавливаемого релиза. Собственная команда `sh install.sh --fingerprint` проверкой не
является: изменённый скрипт может напечатать что угодно. Затем:

```
ECHOFOG_RELEASE_URL=https://example.org/releases/v2 sh install.sh --preset relay --advertise 203.0.113.10 --lang ru
```

Скрипту нужны `curl`, `sha256sum` и `ssh-keygen` (OpenSSH 8.0 и новее, пакет `openssh-client`); без
`ssh-keygen` он останавливается до запуска чего-либо. Он не ставит версию ниже подписанного `min_version`
релиза, ниже порога, вшитого в скрипт, и ниже уже установленной. Осознанный откат выше первых двух границ
требует `--allow-rollback` и печатает предупреждение. При смене ключей релиза старый `install.sh`
останавливается и просит новый; порядок описан в [release-trust.ru.md](release-trust.ru.md).

Установщик создаёт системного пользователя `echofog`, папку данных `/var/lib/echofog` (права 0700),
укреплённый unit systemd и печатает команды для открытия файрвола. Файрвол он не меняет и сервис не
запускает, пока не указан `--start`. Без `--preset` вопросы задаются в терминале (язык, роль, домен,
папка сайта, порт, адрес). С доменом установщик поднимает reality2-quic и reality2-tcp на выбранном
порту, noise3 — на следующем, и выпускает публичную карточку. Пресеты: `relay`, `exit-free` (отдаёт
соединение сервера другим людям: ответственность за этот трафик остаётся на операторе), `home-entry`.
Платный и приватный выход появятся позже.

Запуск: `systemctl enable --now echofog-node`.

## 4. Первый запуск и фраза восстановления

Установщик показывает **фразу восстановления один раз**. Её нужно записать и хранить отдельно от сервера.
В Docker фраза лежит в `recovery-phrase.txt` внутри тома данных (в журнал контейнера она не попадает);
файл нужно скопировать и удалить:

```
docker compose -f deploy/v2/docker-compose.yml exec node cat /data/recovery-phrase.txt
docker compose -f deploy/v2/docker-compose.yml exec node rm /data/recovery-phrase.txt
```

Ключи лежат в папке данных с правами 0600 и не попадают ни в один журнал.

## 5. Проверка доступности

```
echofog-node v2 doctor --data /var/lib/echofog
echofog-node v2 status --data /var/lib/echofog
```

`doctor` проверяет конфигурацию, права на файлы, TCP- и UDP-порты, подключённых пиров, часы,
свободное место на диске, обложку (домен, папку сайта и то, что она своя) и сертификат обложки. Наружу
он ничего не отправляет, пока не указан `--dns`. Доступность порта снаружи определяется по подключению
пира: `status` показывает число сессий и публичную ссылку, если она есть. Оба транспорта нужно разрешить
в файрволе и в панели хостера:

```
ufw allow 443/tcp
ufw allow 443/udp
ufw allow 444/udp
```

## 6. Пресеты и файрвол

| Пресет | Что делает |
|---|---|
| relay | ретранслятор, почтовый ящик и DHT для других; выхода нет |
| exit-free | то же и бесплатный выход |
| home-entry | ретранслятор с отдельным портом приглашений, для проводных сетей (мобильным сетям с белыми списками нужен проверенный адрес) |

Порт приглашений (`ECHOFOG_INVITES=true` или пресет `home-entry`) — ещё один UDP-порт: его тоже нужно
открыть (445 с обложкой, 444 без неё). API оператора слушает только `127.0.0.1` и публиковать его нельзя.

## 7. Обновление

`echofog-node v2 update --manifest-url https://example.org/releases/v2/manifest.bin` ищет более новую
версию, спрашивает согласие перед установкой и никогда не возвращает старую версию. В Docker образ
обновляется сменой тега и перезапуском контейнера.

## 8. Если что-то не работает

- `doctor` сообщает, что порт занят: TCP- или UDP-порт держит другой процесс; его нужно остановить или
  выбрать другой порт.
- Пиры не подключаются: порт закрыт файрволом или панелью хостера.
- Часы расходятся: нужно включить синхронизацию времени (`systemd-timesyncd` или `chrony`).
- «Нет публичной карточки»: у ноды нет обложки, она обслуживает только своих по noise3. Для публичной
  карточки нужны и домен обложки, и папка с собственным сайтом оператора; обложка без сайта отклоняется.
