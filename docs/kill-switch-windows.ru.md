# Kill switch на Windows (режим «весь компьютер», протокол 2)

В режиме «весь компьютер» все приложения идут через VPN. Kill switch делает это обещанием: если
туннель, помощник или приложение погибли, **ничего не выходит с компьютера мимо туннеля**, и так
остаётся, пока защиту не отключат.

## Что это

- **Постоянные фильтры Windows Filtering Platform.** Их хранит служба Base Filtering Engine, а не
  процесс, который их поставил, поэтому убитый помощник, убитое приложение, удалённый адаптер и
  перезагрузка оставляют компьютер закрытым. Фильтры ставятся до подъёма туннеля.
- **Что разрешено мимо туннеля:** loopback; адаптер туннеля; первый хоп живой сессии к выходу (сам
  выход или relay на пути) ровно по его адресу и порту; DHCP на физическом интерфейсе (чтобы аренда
  продлевалась); обнаружение соседей IPv6 с link-local адресами, только когда у выхода есть адрес
  IPv6. Других адресов из карточки выхода **нет**.
- **DNS** только через туннель: порты 53 и 853 вне него закрыты; политика клиента DNS
  `DisableSmartNameResolution` и `DisableParallelAandAAAA` включена; правило разрешения имён для всех
  имён указывает на резолвер внутри туннеля. IPv6 вне туннеля закрыт.
- **Состояние «удержание».** При потере туннеля фильтры остаются, а приложение показывает плашку:
  «Интернет заблокирован намеренно …» и кнопку **Отключить защиту**. То же показывается после падения
  приложения и повторного запуска.

## Идентификаторы

Они не меняются: фильтры прежней версии остались бы бесхозными.

| Что | Значение |
|---|---|
| Провайдер | `{d2c88793-6bad-4fdf-881b-f515c796bdd7}` «EchoFog kill switch» |
| Подуровень | `{af629ec5-2cd7-4717-af0e-b4e3e4672d24}`, вес `0xFFFF` (первый) |
| Имена фильтров | `EchoFog: <правило>`, например `EchoFog: block-all-v4-out` |
| Файл-метка | `%ProgramData%\EchoFog\killswitch.on` (пишет помощник с правами администратора) |
| Правило DNS | правило разрешения имён для `.` с комментарием `EchoFog kill switch` |
| Состояние политики | `HKLM\SOFTWARE\EchoFog\KillSwitchDNS` (прежние значения политики DNS) |

Веса фильтров (внутри подуровня решает подходящий фильтр с наибольшим весом): блок всего `1`;
разрешения (loopback, туннель, LAN, DHCP, обнаружение соседей) `10`; адрес выхода `20`; закрытие
портов DNS на физическом интерфейсе `30`. Уровни: `ALE_AUTH_CONNECT_V4/V6` для исходящих и
`ALE_AUTH_RECV_ACCEPT_V4/V6` для входящих.

Посмотреть: `netsh wfp show filters file=filters.xml`, затем найти ключ провайдера.

## Как снять защиту, если приложение не запускается

Оба способа требуют **терминала с правами администратора** (Запуск от имени администратора) и снимают
одно и то же: все фильтры, подуровень и провайдера, правило DNS, значения политики DNS как были.

1. Через `efv2`:

   ```
   efv2 killswitch status
   efv2 killswitch remove
   ```

2. Без каких-либо программ EchoFog, через PowerShell (скрипт —
   `echofog-core-oss/deploy/v2/killswitch-remove.ps1`; он трогает только фильтры, у которых ключ
   провайдера указанный выше):

   ```
   powershell -ExecutionPolicy Bypass -File .\killswitch-remove.ps1
   ```

   `-List` только считает фильтры и ничего не удаляет.

Встроенной команды `netsh wfp`, которая удаляла бы фильтры, нет, поэтому скрипт пользуется
программным интерфейсом самой службы фильтрации. Крайний случай: точка восстановления системы или
контрольная точка ВМ тоже годится: фильтры — обычная настройка BFE.

## Проверка (только в виртуальной машине)

Фильтры отрезают сеть компьютера, на котором стоят. **Нельзя** запускать эти проверки на рабочем или
общем компьютере: нужна виртуальная машина Hyper-V (сначала контрольная точка) или Windows Sandbox.

1. Интеграционный тест драйвера (собирается один раз на компьютере разработки):

   ```
   cd echofog-core-oss
   set GOWORK=off
   go test -c -tags wfpvm -o wfpvm.test.exe ./internal/v2/tun/winwfp
   ```

   `wfpvm.test.exe` и `internal/v2/tun/winwfp/vm/run-wfpvm.ps1` копируются в ВМ; скрипт запускается в
   PowerShell с правами администратора и отказывается работать вне ВМ. Он ставит настоящие фильтры,
   сверяет `netsh wfp show filters` с ожидаемыми именами и ключом провайдера, проверяет, что Интернет
   закрыт, а loopback нет, заменяет план, удаляет всё и проверяет, что фильтров не осталось.

2. Ручной список (с приложением, в ВМ, захват на физическом интерфейсе ВМ: `pktmon start --capture
   --comp nics` и `pktmon filter add -t tcp udp`, либо фильтр Wireshark `not (ip.addr == <адрес
   выхода>) && not arp && not dhcp`; после каждого шага не меньше 5 минут захвата, с фоновыми
   приложениями):

   - убить помощника туннеля (процесс `--tun-helper`), затем всё приложение;
   - удалить адаптер (`netsh interface set interface EchoFog disable` или диспетчер устройств);
   - DNS: `nslookup example.org 8.8.8.8` не проходит; `nslookup example.org` отвечает; IPv6: `ping -6`
     наружу не проходит;
   - запуск без прав администратора (запрос отклонён): туннель не поднимается, сеть остаётся
     открытой; затем перезагрузка в состоянии удержания: плашка видна, «Отключить защиту» работает;
   - Wi-Fi и Ethernet туда и обратно; сон и пробуждение; смена выхода при включённом режиме;
   - виртуальные адаптеры (Hyper-V, WSL, Docker): считаются физическими и закрыты;
   - сеть только с IPv6; captive portal с DHCP;
   - «Отключить защиту» после неудачного удаления.

   Критерий: ни одного пакета на физическом интерфейсе, кроме адреса выхода (и DHCP с обнаружением
   соседей в пределах линии).
