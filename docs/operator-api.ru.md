# API для владельцев нод: своя оплата и модерация

В EchoFog встроена оплата в TON, но пользоваться ей не обязательно. Если вы держите ноду и хотите
брать деньги по-своему (через бота в Telegram, сайт с оплатой картой, наличными у друзей) или
просто сами решать, кто и сколько пользуется вашей нодой, для этого есть **пропуска**.

Пропуск — это личная ссылка-приглашение на вашу ноду. У каждого пропуска есть:

- своя ссылка (`echofog://join?...`), которая работает в любом приложении EchoFog, как обычное
  приглашение;
- срок: столько-то дней или бессрочно;
- число устройств, которым можно им пользоваться (по умолчанию 2);
- если хотите, объём трафика через ваш выход (столько-то ГБ).

Человек заплатил — вы делаете пропуск и отправляете ему ссылку. Заплатил снова — продлеваете.
Срок кончился или трафик израсходован — его устройства отключаются и не смогут подключиться, пока
вы не продлите пропуск. Отозвать пропуск можно в любой момент, и менять ссылку остальным для этого
не нужно.

Всё это можно делать руками командой `echofog-node pass` или из своей программы через небольшое
HTTP API.

## Что нужно

- Нода в режиме **hidden** или **isolated**: `ECHOFOG_ACCESS=hidden` или `isolated` в
  `deploy/.env`. Публичная нода пускает всех, и пропуска на ней ничего не значат. Подробнее —
  [Скрытые и изолированные ноды](hidden-nodes.ru.md).
- Если берёте оплату по-своему, поставьте `ECHOFOG_EXIT_PRICE=0`. Иначе выход будет ещё и просить
  у владельцев пропусков оплату за гигабайты в TON.
- Для API — адрес и токен, см. ниже.

Общая ссылка ноды (`echofog-node invite`) продолжает работать рядом с пропусками. Кто вошёл по
ней, тот остаётся. Давайте её только тем, кого пускаете насовсем, или не давайте никому.

## Руками: `echofog-node pass`

На сервере, в папке `deploy/`:

```bash
docker compose exec node echofog-node pass new --days 30 --devices 2 --label "Аня"
```

```
Pass 3f9a1c07be12 (active)  Аня
Term:     until 2026-11-28 14:05
Devices:  0 of 2
Traffic:  0 B used
Link (give it to that person only):
echofog://join?v=1&net=echofog&p=102&id=5f09...&s=...&a=203.0.113.24%3A443
```

| Команда | Что делает |
|---|---|
| `pass list` | все пропуска: состояние, срок, устройства, трафик, подпись |
| `pass new --days 30 --devices 2 --gb 100 --label "..."` | новый пропуск; `--days 0` — бессрочно, `--gb 0` — без лимита трафика |
| `pass show ID` | один пропуск с устройствами и ссылкой |
| `pass extend ID --days 30` | добавить 30 дней (к концу срока или от сегодня, если срок кончился) |
| `pass extend ID --gb 50` | добавить 50 ГБ |
| `pass extend ID --days 30 --reset` | ещё месяц, трафик считается заново |
| `pass revoke ID` | остановить сейчас и отключить устройства (`extend` вернёт) |
| `pass delete ID` | удалить |

Каждая команда запускается так: `docker compose exec node echofog-node pass ...`.

## Из своей программы: HTTP API

Включите в `deploy/.env`:

```bash
ECHOFOG_API_ADDR=0.0.0.0:8090
ECHOFOG_API_TOKEN=<не короче 16 символов, например из: openssl rand -hex 24>
```

и в `deploy/docker-compose.yml` раскомментируйте строку под `ports`:

```yaml
      - "127.0.0.1:8090:8090"
```

Потом `docker compose up -d`. API доступно по адресу `http://127.0.0.1:8090` на самом сервере.
Так и оставьте: бот или сайт на том же сервере до него достучатся, а интернет — нет. Если бот
работает на другой машине, поставьте перед API HTTPS (например, Caddy как обратный прокси) и
никогда не отправляйте токен по обычному HTTP.

В каждом запросе передаётся токен:

```
Authorization: Bearer <токен>
```

### Запросы

| Запрос | Тело | Ответ |
|---|---|---|
| `GET /api/v1/node` | | `{"mode", "link", "joined", "passes"}` |
| `GET /api/v1/passes` | | все пропуска, новые сначала |
| `POST /api/v1/passes` | `{"label", "days", "devices", "gb"}` (всё необязательно) | новый пропуск, `201` |
| `GET /api/v1/passes/{id}` | | один пропуск |
| `POST /api/v1/passes/{id}/extend` | `{"days", "gb", "devices", "label", "resetUsage"}` | пропуск |
| `POST /api/v1/passes/{id}/revoke` | | пропуск, теперь `revoked` |
| `DELETE /api/v1/passes/{id}` | | `204` |
| `DELETE /api/v1/passes/{id}/devices/{peerId}` | | `204`: освобождает место одного устройства |

Пропуск выглядит так:

```json
{
  "id": "3f9a1c07be12",
  "label": "tg:123456789",
  "link": "echofog://join?v=1&net=echofog&...",
  "state": "active",
  "created": 1793023500,
  "expires": 1795615500,
  "maxDevices": 2,
  "quotaBytes": 107374182400,
  "usedBytes": 5368709120,
  "devices": [
    {"peerId": "a1b2...", "joinedAt": 1793023800, "connected": true}
  ]
}
```

- `state`: `active` (действует), `expired` (срок вышел), `used_up` (трафик израсходован) или
  `revoked` (отозван).
- `expires` равен 0 у бессрочного пропуска; время везде в секундах Unix.
- `quotaBytes` равен 0, если лимита трафика нет; `usedBytes` считает трафик через ваш выход в обе
  стороны.
- `label` — ваше поле: положите туда Telegram ID покупателя или номер заказа, чтобы потом найти
  пропуск.
- При создании `days: 0` значит бессрочно, `devices: 0` — два устройства, `gb: 0` — без лимита. При
  продлении `days` и `gb` прибавляются, а `devices` и `label` меняются, только если вы их передали.
  Продление снимает и отзыв.

Ошибки приходят в виде `{"error": "..."}`: `401` без правильного токена, `404` для неизвестного
пропуска, `409`, если нода не скрытая и не изолированная, `400` для неправильного запроса.

### Попробовать через curl

```bash
T=<токен>
curl -s -H "Authorization: Bearer $T" -d '{"label":"Аня","days":30,"gb":100}' http://127.0.0.1:8090/api/v1/passes
curl -s -H "Authorization: Bearer $T" http://127.0.0.1:8090/api/v1/passes
curl -s -H "Authorization: Bearer $T" -d '{"days":30}' http://127.0.0.1:8090/api/v1/passes/3f9a1c07be12/extend
curl -s -H "Authorization: Bearer $T" -X POST http://127.0.0.1:8090/api/v1/passes/3f9a1c07be12/revoke
```

## Как это можно использовать

### Бот в Telegram с подпиской на месяц

1. Пользователь пишет боту `/buy`. Бот показывает кнопку оплаты того платёжного сервиса, которым
   вы пользуетесь.
2. Платёжный сервис сообщает боту, что оплата прошла.
3. Бот ищет пропуск с `label` = Telegram ID пользователя (`GET /api/v1/passes`). Если его нет,
   создаёт: `POST /api/v1/passes {"label":"tg:123456789","days":30,"devices":2}`. Если есть,
   продлевает: `POST /api/v1/passes/{id}/extend {"days":30}`.
4. Бот отправляет пользователю `link`. Пользователь вставляет её в EchoFog (Прокси → Конкретная
   нода).

Месяц кончился, а пользователь не заплатил — вам ничего не нужно делать: пропуск истечёт, и его
устройства отключатся. Заплатит позже — шаг 3 продлит тот же пропуск, и та же ссылка снова
заработает.

Короткий набросок на Python (`requests`), только та часть, что общается с нодой:

```python
import requests

API = "http://127.0.0.1:8090/api/v1"
HEAD = {"Authorization": "Bearer " + TOKEN}

def paid(tg_id: int, days: int = 30) -> str:
    label = f"tg:{tg_id}"
    passes = requests.get(f"{API}/passes", headers=HEAD).json()
    mine = next((p for p in passes if p["label"] == label), None)
    if mine is None:
        mine = requests.post(f"{API}/passes", headers=HEAD,
                             json={"label": label, "days": days, "devices": 2}).json()
    else:
        mine = requests.post(f"{API}/passes/{mine['id']}/extend", headers=HEAD,
                             json={"days": days}).json()
    return mine["link"]  # это отправить пользователю
```

### Сайт с оплатой

Всё так же, как с ботом: платёжный сервис вызывает вебхук вашего сайта, сайт создаёт или
продлевает пропуск с номером заказа или покупателя в `label` и показывает ссылку на странице
«спасибо» или отправляет её письмом. Личный кабинет может показывать остаток из
`GET /api/v1/passes/{id}`: `expires`, `usedBytes` из `quotaBytes` и какие устройства сейчас в сети.

### Пакеты трафика вместо срока

Продавайте гигабайты: `{"gb": 50}` без `days`. Когда пакет израсходован, пропуск становится
`used_up`, и устройства отключаются. Следующая покупка добавляет к нему: `extend {"gb": 50}`. Можно
и вместе: месяц и 200 ГБ, каждый месяц `extend {"days": 30, "gb": 200, "resetUsage": true}`.

### Пробный период

`{"days": 1, "devices": 1, "label": "trial:..."}`. Если человек купит, продлите тот же пропуск: уже
настроенная у него ссылка продолжит работать.

### Семья и друзья, без денег

По пропуску на человека, бессрочно: `pass new --label "мама"`. Потерялся телефон — уберите это
устройство (`DELETE .../devices/{peerId}`), и человек войдёт заново с нового. Не хотите больше
делиться с кем-то — отзовите его пропуск, остальным ничего менять не нужно. С общей ссылкой
пришлось бы делать новую и рассылать всем.

### Модерация

`GET /api/v1/passes` показывает, кто сколько тратит и какие устройства подключены. Пропуск съедает
месячный трафик — дайте ему лимит (`extend {"gb": ...}` для пропуска без лимита его установит) или
отзовите. Лимит бесплатного трафика для всех сразу задаётся настройками выхода, см.
[Запуск ноды](run-a-node.ru.md).

## Что стоит помнить

- **Ссылка — это ключ.** Кто знает ссылку пропуска, тот может им пользоваться в пределах числа
  устройств. Отправляйте её только этому человеку. Утекла — отзовите пропуск и сделайте новый.
- **У каждой ноды свои пропуска.** Если серверов несколько, сделайте пропуск на каждом и отправьте
  все ссылки, или запустите их с одним общим секретом и общей ссылкой
  ([Скрытые и изолированные ноды](hidden-nodes.ru.md)).
- **Трафик считается на вашем выходе** в обе стороны. Он сохраняется раз в 30 секунд, так что при
  падении теряется не больше этого.
- **На одной ноде не больше 10 000 пропусков.** Удаляйте старые, которые больше не нужны.
- **Выход видит, куда ходят люди**, как любой VPN-выход: адреса и имена сайтов. Скажите об этом
  покупателям; содержимое защищает HTTPS самих сайтов.
- **Токен — это всё API.** У кого он есть, тот может создавать пропуска. Не кладите его в
  публикуемый код и держите API на loopback.
- EchoFog — экспериментальная программа. Аудита не было, против настоящего государственного DPI её
  не проверяли. Если продаёте доступ, скажите об этом тем, кто платит.
