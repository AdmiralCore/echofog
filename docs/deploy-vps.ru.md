# Нода на VPS через Docker

Подойдёт любой VPS с публичным IP и Ubuntu или Debian. Здесь короткий рецепт; что значат роли и
настройки — в [Своя нода](run-a-node.ru.md).

## 1. Подключитесь и поставьте Docker

```bash
ssh root@<IP сервера>
```

```bash
curl -fsSL https://get.docker.com | sh
```

Если заходите не под root, а обычным пользователем, добавьте себя в группу `docker` и перезайдите:
`sudo usermod -aG docker "$USER"`.

## 2. Откройте порт

Нода использует один порт и для UDP (QUIC), и для TCP (запасной путь для сетей, где режут UDP).
Compose-файл публикует его как **443**. Если на сервере `ufw`:

```bash
ufw allow 443/udp && ufw allow 443/tcp
```

Если у провайдера есть свой файрвол в панели управления, откройте UDP и TCP 443 и там. **Главное —
UDP 443**: по нему идёт QUIC, а через него почти весь трафик, тогда как в облачных файрволах обычно
открыт только TCP. В Google Cloud:

```bash
gcloud compute firewall-rules create echofog --allow udp:443,tcp:443
```

## 3. Скачайте код и настройте

```bash
git clone https://github.com/AdmiralCore/EchoFog.git
cd EchoFog/echofog-core-oss
cp deploy/.env.example deploy/.env
nano deploy/.env
```

Главные настройки:

```bash
# сервер: релей, почтовые ящики для других, DHT, выход; своих чатов, звонков и файлов нет
ECHOFOG_ROLE=server
# только сигнальная нода (DHT + помощь с пробивкой NAT, без трафика) — дёшево; false — полноценный релей
ECHOFOG_SIGNALING=false
ECHOFOG_RELAY=true
# раздавать подключение сервера как платный выход (чужой трафик выходит с его IP)
ECHOFOG_EXIT=false
ECHOFOG_ADVERTISE_PORT=443
# пусто — входить через встроенную ноду; или адреса знакомых нод (они её заменяют)
ECHOFOG_BOOTSTRAP=
```

`ECHOFOG_ROLE=server` — то, что нужно VPS: нода держит сетевые службы и ни одной службы
мессенджера (чаты, контакты, звонки, передача файлов), а кадры этих видов отбрасывает сразу, не
расшифровывая и не сохраняя. Написать или позвонить самой ноде нельзя, но сообщения между другими
людьми через неё идут и ждут в её почтовом ящике, пока получатель офлайн. Compose ставит `server`,
даже если в `.env` нет `ECHOFOG_ROLE` (старая копия); `ECHOFOG_ROLE=client` ставьте, только если
хотите пользоваться нодой ещё и как своим мессенджером. Подробнее —
[Сервер или клиент](run-a-node.ru.md#сервер-или-клиент).

## 4. Запустите

```bash
docker compose -f deploy/docker-compose.yml pull
docker compose -f deploy/docker-compose.yml up -d
docker compose -f deploy/docker-compose.yml logs -f
```

При первом запуске нода печатает **фразу восстановления** — запишите её и храните не в сети, она
восстанавливает личность и кошелёк ноды. Ещё она печатает **адрес подключения** (Join address):
`<this server's public IP or domain>:443/<peer id>`. Подставьте IP сервера — этот адрес другие
ноды указывают в `ECHOFOG_BOOTSTRAP`, а пользователи приложения вставляют в
**Настройки → Бутстрап-ноды**.

Сводка при старте в логе и
`docker compose -f deploy/docker-compose.yml exec node echofog-node status` показывают `Role: server`.

Проверьте, что всё в порядке:

```bash
docker compose -f deploy/docker-compose.yml ps
```

## Раздача интернета (выход)

Чтобы через сервер можно было ходить в интернет другим людям (или только вашим устройствам),
задайте в `deploy/.env`:

```bash
ECHOFOG_EXIT=true
ECHOFOG_EXIT_PRICE=0.05          # долларов за ГБ; 0 = бесплатно для всех
ECHOFOG_EXIT_UPLOAD_MBPS=100     # примерно столько, сколько есть у сервера; на новом сервере не 0
# ваши устройства ходят бесплатно и без дневного лимита (ключ — в приложении: Прокси → Релей → Ваш ключ)
ECHOFOG_EXIT_FREE_PEERS=<peer id>,<peer id>
```

При `ECHOFOG_EXIT_UPLOAD_MBPS=0` нода сначала меряет скорость о других пиров; на новом сервере их
часто ещё нет, и в логе появляется `Exit sharing not started: no peers to measure upload speed
against`. На платном выходе каждому, кого нет в бесплатном списке, даётся 512 КБ пробного трафика
в день, дальше — только за оплату.

Строка статистики в логе считает отказы по причинам, например `exit: 12 sessions, 30 refused
(payment required 28, dial failed 2)`, а каждый отказ пишется как `refused stream` (не чаще раза
в 30 секунд на причину). Приложение на странице Прокси показывает, почему выход его не
обслуживает: выход выключен, бесплатный трафик кончился или выход не отвечает.

**Платному выходу нужно немного TON на кошельке самой ноды.** Клиенты обычно платят со своего
депозита, а забрать эти деньги — транзакция, комиссию за которую платит кошелёк ноды (около
0,015 TON каждая). С пустым кошельком оплата ждёт, а строка статистики пишет `vouchers: … owed,
… cashed (the node wallet has no TON …)`. Положите 0,1–0,2 TON на адрес из `echofog-node status`
(в testnet — Telegram-бот @testgiver_ton_bot). Подробнее — [Как нода получает деньги](vault-payments.ru.md#сначала-положите-немного-ton-на-кошелёк-ноды).

## Выход только для приглашённых

Чтобы выход не попадал в общий список и обслуживал только тех, кому вы дали ссылку, добавьте в
`deploy/.env` (рядом с `ECHOFOG_EXIT=true`):

```bash
ECHOFOG_ACCESS=isolated          # или hidden, см. ниже
```

затем `docker compose -f deploy/docker-compose.yml up -d` и возьмите ссылку:

```bash
docker compose -f deploy/docker-compose.yml exec node echofog-node invite
```

- **isolated** (изолированный): нода не входит в сеть и никуда не подключается сама; владельцы
  ссылки подключаются прямо к опубликованному порту. Обычный выбор для VPS.
- **hidden** (скрытый): нода пользуется сетью как клиент (пригодится, если до порта не
  достучаться: тогда в ссылке будет и релей), но не видна в сети и ни для кого не работает релеем.

В ссылку идёт публичный IP сервера (его нода узнаёт через STUN) с портом `ECHOFOG_ADVERTISE_PORT`
(в этом compose — 443). Для домена или сервера с несколькими IP задайте
`ECHOFOG_PUBLIC_ADDR=vpn.example.org:443`. Секрет создаётся при первом запуске и хранится в томе
`echofog-data`, так что ссылка переживает перезапуски и обновления. `invite --rotate` делает новую
ссылку, `invite --list` показывает, кто подключился, `invite --remove <peer id>` отключает
человека. Чтобы одна ссылка работала на нескольких серверах, дайте им один секрет: создайте его
командой `docker compose -f deploy/docker-compose.yml run --rm node invite --new-secret` и
положите в `ECHOFOG_ACCESS_SECRET` (или в Docker secret через `ECHOFOG_ACCESS_SECRET_FILE`, см.
compose-файл). Цена — по-прежнему `ECHOFOG_EXIT_PRICE`; `ECHOFOG_EXIT_UPLOAD_MBPS` не нужен.
Подробнее — [Скрытые и изолированные ноды](hidden-nodes.ru.md).

## TCP-обход

Нода притворяется настоящим сайтом из своего дата-центра: клиенты подключаются к ней так, как
Chrome открыл бы этот сайт, а цензор, который подключится без секрета, попадёт на сам сайт. Свой
домен для этого не нужен. Нода находит такой сайт сама: при старте среди 20 адресов в каждую
сторону от своего, а если там ничего не подошло, в фоне ищет по всей своей `/24` и соседним `/24`
(не чаще раза в 12 часов и медленно, хостеры не любят сканирование портов). Берётся только сайт с
сертификатом от публичного центра сертификации на настоящий домен, который отвечает по TLS 1.3 так
же, как нода. Пока сайта нет, нода работает только по UDP и пишет в лог предупреждение `ANTI-DPI`, а
когда найдёт, сама включит TCP.

Чтобы увидеть подходящие сайты сразу или выбрать сайт самому, выполните в `deploy/`:

```bash
docker compose run --rm node camouflage
```

Команда проверит те же адреса (несколько минут) и напечатает две строки для `deploy/.env`:

```bash
ECHOFOG_TLS_SERVER_NAME=<домен сайта>
ECHOFOG_CAMOUFLAGE_ADDR=<IP сайта>:443
```

Затем `docker compose up -d` и разошлите новую ссылку из `invite`. Если команда ничего не нашла,
рядом с сервером подходящих сайтов нет. Тогда подойдёт и свой сайт: направьте домен на другой
маленький сервер в том же дата-центре и раздавайте с него HTTPS с настоящим сертификатом (Caddy
получает его сам).

Те же две строки включают и маскировку UDP: клиенты будут подключаться к ноде так, как Chrome
открыл бы этот сайт по HTTP/3. Если сайт сам умеет HTTP/3, зонд по UDP получит его настоящий ответ.
Ссылки-приглашения скрытой ноды несут имя сайта сами; публичный адрес раздавайте в виде
`<IP>:443/<peer id>?sni=<домен сайта>&srv=1`, чтобы и первое подключение было замаскировано.

Подробнее — [Anti-DPI](anti-dpi.ru.md).

## Защита

Сборка выше уже запускает ноду в роли сервера (`ECHOFOG_ROLE=server`): без чата, звонков и
передачи файлов, только то, что нужно ретранслятору и выходу. Лимиты против наплыва соединений,
бесплатных ID и злоупотреблений включены по умолчанию. Две вещи стоит задать самим в
`deploy/.env`:

- `ECHOFOG_RELAY_MBPS` ниже исходящего канала по тарифу, чтобы ретранслируемый трафик оставлял
  место выходу и самой ноде;
- `ECHOFOG_WS_CLIENT_IP_HEADER=CF-Connecting-IP`, если WebSocket идёт через Cloudflare и его порт
  доступен только через CDN.

В файрволе провайдера держите открытым только порт ноды. Что делает каждая защита, как увидеть её
в `status` и в логе и чего она не покрывает (наплыв, забивающий канал, требует DDoS-защиты
провайдера): [Защита ноды](node-security.ru.md).

## Обновление

```bash
cd ~/EchoFog && git pull          # папка, куда вы клонировали на шаге 3; подтянет изменённый compose-файл
cd echofog-core-oss
docker compose -f deploy/docker-compose.yml pull
docker compose -f deploy/docker-compose.yml up -d
```

Личность, база и кошелёк лежат в томе `echofog-data` и переживают обновления.

### Готовый образ

Compose-файл запускает `ghcr.io/admiralcore/echofog-node:latest`, который GitHub собирает при
каждом пуше в `main` (для `amd64` и `arm64`), так что сервер скачивает около 30 МБ и ничего не
компилирует. Сборка готова примерно через десять минут после пуша; до этого `pull` оставляет
предыдущую. У каждой сборки есть и метка с коммитом, например `sha-4d6bfaa`: впишите
`ECHOFOG_IMAGE=ghcr.io/admiralcore/echofog-node:sha-4d6bfaa` в `deploy/.env`, чтобы остаться на одной
сборке или вернуться к ней.

Чтобы собрать из своей копии кода (нужно около 4 ГБ свободного места), добавьте файл сборки:

```bash
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.build.yml up -d --build
```

Если сборка падает с `no space left on device`, диск забили старые слои сборки:
`docker builder prune -af` и `docker image prune -af` освобождают их, не трогая данные ноды.

## Очистка устаревших данных

Нода убирает за собой сама: записи DHT истекают, пиры, до которых долго не достучаться,
забываются, почта старше недели удаляется. Если в ней всё же застряло старое (нода переехала или
сменила ключ, после большого теста осталось много ушедших пиров), сбросьте то, что она узнала от
сети, — через несколько минут она узнает это заново:

```bash
cd ~/EchoFog/echofog-core-oss
docker compose -f deploy/docker-compose.yml stop node
docker compose -f deploy/docker-compose.yml run --rm node clean            # --dry-run, чтобы сначала посчитать
docker compose -f deploy/docker-compose.yml up -d
```

Удаляются записи DHT, известные пиры и их адреса, оценки выходов и чужие ключи в кеше. Ключ ноды,
кошелёк, учёт оплат выхода, секрет доступа и список приглашённых в скрытую ноду не трогаются
никогда. `--mail` удаляет ещё и почту, которую нода хранит для людей не в сети (они её потеряют),
`--bans` — баны нарушителей. Не удаляйте том `echofog-data` ради «чистки»: вместе с ним пропадёт
ключ ноды, и все ссылки и клиенты, которые его знают, перестанут работать.
