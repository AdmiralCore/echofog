# Kill switch на Linux (режим «весь компьютер», протокол 2)

В режиме «весь компьютер» весь трафик приложений идёт через VPN. Kill switch делает это
обещанием: если туннель, помощник или приложение завершились, **ничего не выходит из компьютера
мимо туннеля**, и так остаётся, пока защиту не отключат.

## Что это

- **Таблица nftables в ядре.** Таблица `inet echofog_ks` содержит две цепочки: `out` (хук
  `output`, приоритет 0) и `in` (хук `input`, приоритет 0), у обеих политика `drop`. Таблицу
  хранит ядро, а не установивший её процесс: убитый помощник, убитое приложение, удалённое
  устройство и упавшая сессия оставляют компьютер закрытым. Правила ставятся до подъёма туннеля.
- **Одна транзакция.** Замена — это один сценарий `nft -f` (`add table`, `flush table`, новые
  цепочки и правила), nftables применяет его атомарно: момента без фильтров нет, а неудачный
  сценарий ничего не меняет.
- **Что разрешено мимо туннеля:** петля; устройство туннеля `echofog0`; первый хоп живой сессии до
  выхода (сам выход или релей в пути) — ровно его адрес, порт и протокол; DHCP, если план это
  разрешает; обнаружение соседей IPv6 с link-local адресами и только при IPv6-адресе выхода.
- **DNS** идёт только через туннель: порты 53 и 853 заблокированы на всех интерфейсах, кроме
  туннеля; `resolvectl` делает `echofog0` маршрутом по умолчанию для systemd-resolved и снимает его
  с тех интерфейсов, у которых он был. Серверы, домены поиска и флаги default-route этих
  интерфейсов сохраняются до изменения и возвращаются при Restore, в том числе из нового процесса
  после падения.
- **Состояние Held.** Когда туннель потерян, фильтры остаются, а приложение показывает плашку с
  кнопкой **«Отключить защиту»**. Она же показывается после падения приложения и нового запуска.
- **Перезагрузка очищает таблицу.** В отличие от фильтров Windows, правила nftables не
  восстанавливаются ядром после перезагрузки: сеть открыта, пока режим не включат снова. Это то же
  состояние, что и до первого запуска; ничего от EchoFog в это время компьютер закрытым не держит.

## Идентификаторы

Они не меняются: иначе фильтры прошлой версии останутся сиротами.

| Что | Значение |
|---|---|
| Таблица | `inet echofog_ks` |
| Цепочки | `out` = хук `output`, `in` = хук `input`; приоритет `0`; политика `drop` |
| Порядок правил (первое совпадение) | порты DNS `30`, адреса выхода `20`, разрешения (петля, туннель, DHCP, LAN, ND) `10`, блокировка всего `1` |
| Устройство туннеля | `echofog0` (TUN из v1 `tunmode`; правила называют его) |
| Файл-метка | `/run/echofog/killswitch.on` (пишет помощник с правами root) |
| Снимок DNS | `/run/echofog/killswitch-dns.json` (что было у `resolvectl` до Protect) |

Посмотреть правила: `sudo nft list table inet echofog_ks`.

Помощник — тот же исполняемый файл, запущенный как `--ks-helper`; права запрашиваются через
`pkexec` (polkit). Устройство TUN и tun2socks поднимает этот же помощник, поэтому второй запрос
прав не появляется.

## Как снять защиту, если приложение не запускается

Через `efv2` (удаляет таблицу **и** возвращает настройки DNS):

```
sudo efv2 killswitch remove
efv2 killswitch status          # читает метку, права root не нужны
```

Без программ EchoFog (только фильтры, DNS не возвращается):

```
sudo nft delete table inet echofog_ks
sudo resolvectl revert echofog0
sudo resolvectl flush-caches
```

`efv2 killswitch remove` на компьютере, где ничего этого нет, ничего не удаляет и завершается
успешно. Без root он сообщает об этом и ничего не меняет.

## Требования

`nft` (nftables), `resolvectl` (systemd-resolved), `ip` (iproute2), polkit для запроса прав и ядро с
TUN и nftables. Без systemd-resolved часть DNS отказывает и режим не запускается: фильтры
заблокировали бы DNS, а резолвера в туннеле не было бы. Перенаправление для систем только с
`resolv.conf` в эту версию не входит.

## Проверка (только в WSL или виртуальной машине)

Таблица режет сеть того компьютера, где стоит. **Никогда** не проводите эти проверки на рабочей
или общей машине: используйте экземпляр WSL или виртуальную машину (сначала сделайте снимок).

1. Интеграционный тест (root; ставит настоящие правила, убивает помощника через `kill -9`,
   слушает `eth0`, затем всё снимает):

   ```
   cd echofog-core-oss
   sudo EF_KS_INTEGRATION=1 go test -tags kslinux ./internal/v2/tun/platform -run Integration -v
   ```

   Он проверяет, что таблица стоит после `kill -9`, что разрешённая датаграмма доходит до `eth0`,
   а датаграмма на порт 53 — нет, и что `efv2 killswitch remove` (тот же `RemoveAll`) возвращает
   настройки DNS. Для части с DNS используется пустышка `echofog0`; настоящий TUN и tun2socks
   требуют живого выхода и проверяются вручную.

2. Ручной список (в ВМ, с живым узлом и захватом на физическом интерфейсе:
   `sudo tcpdump -i eth0 -n 'udp port 53 or port 853'`, не меньше 5 минут после каждого шага, с
   фоновыми приложениями):

   - убить помощника (`kill -9` процесса `--ks-helper`), затем всё приложение;
   - удалить устройство (`sudo ip link del echofog0`);
   - DNS: `resolvectl query example.org` идёт через `198.18.0.2`; запрос к публичному резолверу на
     порт 53 не покидает `eth0`; IPv6 мимо туннеля заблокирован;
   - запуск без root (запрос polkit отклонён): туннель не поднимается, сеть остаётся открытой;
     затем запуск в состоянии Held: показывается плашка и работает «Отключить защиту»;
   - Wi-Fi ↔ Ethernet; сон и пробуждение; смена выхода при включённом режиме;
   - сеть только с IPv6; captive portal с DHCP;
   - «Отключить защиту» после неудачного снятия.

   Критерий: ни один пакет не уходит на физический интерфейс, кроме адреса выхода (и DHCP и
   обнаружения соседей по каналу), и ни один пакет на порты 53 и 853 не уходит никогда.
