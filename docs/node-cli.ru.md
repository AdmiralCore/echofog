# Командная строка ноды: все команды и флаги

`echofog-node` запускается на сервере (в Docker или напрямую). В Docker Compose контейнер выполняет
`echofog-node run`, остальные команды запускаются рядом с ним. Здесь собраны все. Тот же список всегда
можно получить у самого бинарника: `echofog-node help` и `echofog-node <команда> -h`.

Любой флаг можно задать и переменной окружения: имя флага заглавными буквами, дефисы заменены на
подчёркивания, спереди `ECHOFOG_` (`--exit-price` это `ECHOFOG_EXIT_PRICE`). В Docker Compose их кладут
в `environment:` сервиса `node` в `deploy/docker-compose.yml`.

## Шпаргалка по Docker

Все команды выполняются на сервере в папке, где лежит `deploy/`. `exec` обращается к работающей ноде;
`run --rm` запускает одноразовый контейнер на тех же данных: так выполняют команды, которым нужна
остановленная нода.

| Что нужно | Команда |
|---|---|
| запустить / остановить / перезапустить | `docker compose -f deploy/docker-compose.yml up -d` / `stop node` / `restart node` |
| смотреть лог (при первом запуске в нём фраза восстановления) | `docker compose -f deploy/docker-compose.yml logs -f node` |
| что делает нода: пиры, ретранслированный трафик, заработок | `docker compose -f deploy/docker-compose.yml exec node echofog-node status` |
| то же в JSON | `... exec node echofog-node status --json` |
| проверка здоровья (только код возврата) | `... exec node echofog-node status --quiet` |
| адрес и баланс TON-кошелька | `... exec node echofog-node wallet` |
| получить ссылку-приглашение скрытой или изолированной ноды | `... exec node echofog-node invite` |
| кто вошёл по ссылке | `... exec node echofog-node invite --list` |
| новая ссылка (по старой больше никто не войдёт) | `... exec node echofog-node invite --rotate` |
| убрать человека из списка | `... exec node echofog-node invite --remove <peer id>` |
| новый секрет доступа (нода не нужна) | `... run --rm node invite --new-secret` |
| очистить то, что нода узнала из сети (устаревшие пиры, записи DHT, рейтинги) | `docker compose -f deploy/docker-compose.yml stop node`, затем `... run --rm node clean`, затем `... up -d` |
| то же, плюс почта для офлайн-людей и баны | `... run --rm node clean --mail --bans` (с `--dry-run` только посчитает) |
| версия | `... exec node echofog-node version` |
| обновить | `docker compose -f deploy/docker-compose.yml pull`, затем `up -d` |
| начать с нуля: удалить данные ноды (личность, кошелёк, всё) | `docker compose -f deploy/docker-compose.yml down`, затем удалить том с данными (`docker volume ls` покажет его, имя вроде `deploy_echofog-data`; потом `docker volume rm <имя>`). **Это уничтожает личность и кошелёк: сначала запишите фразу восстановления.** |
| восстановить личность по фразе | остановите ноду, положите фразу в файл и выполните `... run --rm -v $PWD/phrase.txt:/phrase.txt node restore --mnemonic-file /phrase.txt` (`--force` заменит существующую) |
| создать личность, не запуская ноду | `... run --rm node init` |

`...` означает `docker compose -f deploy/docker-compose.yml`. Без Docker те же команды запускают
напрямую: `echofog-node status`, `echofog-node clean` и так далее.

## Команды

| Команда | Что делает |
|---|---|
| `run` | запускает ноду (по умолчанию, если команда не указана) |
| `init` | создаёт новую личность и печатает её фразу восстановления |
| `restore` | восстанавливает личность по фразе восстановления |
| `status` | показывает, что делает работающая нода |
| `wallet` | показывает адрес и баланс TON-кошелька работающей ноды |
| `invite` | ссылка-приглашение работающей ноды (скрытой или изолированной) |
| `pass` | личные ссылки скрытой ноды со сроком, числом устройств и трафиком (list, new, show, extend, revoke, delete) |
| `clean` | удаляет устаревшие сетевые данные остановленной ноды |
| `camouflage` | ищет рядом с сервером настоящие сайты, под которые нода может маскироваться |
| `version` | печатает версию |

### `status` и `wallet`

| Флаг | Что делает |
|---|---|
| `--json` | печатает исходный JSON |
| `--quiet` | ничего не печатает; по коду возврата видно, отвечает ли нода (для проверок здоровья) |
| `--status-addr` строка | адрес страницы статуса работающей ноды (по умолчанию "127.0.0.1:7070") |

### `invite`

| Флаг | Что делает |
|---|---|
| `--app` | печатает только ссылку echofog://, без её https-формы |
| `--list` | список пиров, вошедших по ссылке |
| `--new-secret` | печатает новый секрет доступа для --access-secret / ECHOFOG_ACCESS_SECRET (работающая нода не нужна) |
| `--remove` строка | убирает этот peer ID из списка вошедших |
| `--rotate` | делает новый секрет доступа: по старой ссылке больше никто не войдёт, вошедшие остаются |
| `--status-addr` строка | адрес страницы статуса работающей ноды (по умолчанию "127.0.0.1:7070") |

### `pass`

`echofog-node pass <list|new|show|extend|revoke|delete> [ID] [флаги]`. Пропуска — это личные
ссылки-приглашения скрытой или изолированной ноды, у каждого свой срок, число устройств и, если
нужно, лимит трафика. Сделайте пропуск, когда человек заплатил (или для друга), продлите, когда он
заплатит снова, отзовите, чтобы его отключить. Бот или сайт делает то же через API оператора:
[operator-api.ru.md](operator-api.ru.md).

| Флаг | Что делает |
|---|---|
| `--label` строка | ваша пометка на пропуске: имя, номер заказа |
| `--days` число | срок в днях (new: 0 — бессрочно; extend: сколько дней добавить) |
| `--devices` число | сколько устройств могут им пользоваться (new: 0 — 2) |
| `--gb` число | трафик через выход, в ГБ (new: 0 — без лимита; extend: сколько ГБ добавить) |
| `--reset` | extend: начать счёт трафика заново (месячный лимит) |
| `--status-addr` строка | адрес страницы статуса работающей ноды (по умолчанию "127.0.0.1:7070") |

### `camouflage`

Ищет рядом с сервером настоящие сайты, под которые нода может маскироваться: сайты с общепризнанным
сертификатом на настоящий домен, которые отвечают по TLS 1.3 точно так же, как нода. Сначала
проверяет собственную /24 сервера, затем соседние, по нескольку адресов за раз, и печатает найденное
вместе с двумя строками для `deploy/.env`. Публичная нода ищет так же сама; эта команда нужна, когда
в логе написано, что сайт не найден, или чтобы выбрать сайт самому. В Docker:
`docker compose run --rm node camouflage` в `deploy/`.

| Флаг | Что делает |
|---|---|
| `--ip` строка | публичный IPv4-адрес сервера (по умолчанию: ECHOFOG_PUBLIC_ADDR, адрес интерфейса или то, что видит STUN) |
| `--max` число | остановиться после стольких подходящих сайтов (по умолчанию 5) |

### `init`

| Флаг | Что делает |
|---|---|
| `--data-dir` строка | где лежат база и личность (по умолчанию "/data") |
| `--password` строка | пароль, которым шифруется личность (лучше --password-file; без обоих пароль генерируется и хранится в папке данных) |
| `--password-file` строка | файл с паролем (например, секрет Docker) |

### `restore`

| Флаг | Что делает |
|---|---|
| `--data-dir` строка | где лежат база и личность (по умолчанию "/data") |
| `--force` | заменить личность, которая уже есть в папке данных |
| `--mnemonic` строка | фраза восстановления (видна в списке процессов: лучше --mnemonic-file или запрос) |
| `--mnemonic-file` строка | файл с фразой восстановления |
| `--passphrase` строка | дополнительная кодовая фраза, если фраза восстановления создавалась с ней |
| `--password` строка | пароль, которым шифруется личность (лучше --password-file; без обоих пароль генерируется и хранится в папке данных) |
| `--password-file` строка | файл с паролем (например, секрет Docker) |

### `clean`

Нода должна быть остановлена: база открывается только в одном процессе. Личность, TON-кошелёк, учёт
выхода, секрет доступа и список вошедших в скрытую ноду никогда не трогаются.

| Флаг | Что делает |
|---|---|
| `--bans` | заодно забыть баны пиров, которые себя плохо вели |
| `--data-dir` строка | где лежат база и личность (по умолчанию "/data") |
| `--dry-run` | только посчитать, что будет удалено |
| `--mail` | заодно удалить почту, которая ждёт офлайн-людей (для них она пропадёт) |
| `--password` строка | пароль, которым шифруется личность (лучше --password-file; без обоих пароль генерируется и хранится в папке данных) |
| `--password-file` строка | файл с паролем (например, секрет Docker) |

## `run`: все флаги

### Личность и данные

| Флаг | Переменная окружения | Что делает |
|---|---|---|
| `--access` строка | `ECHOFOG_ACCESS` | кто может достучаться до ноды: public (в списке сети, её выход объявлен), hidden (пользуется сетью как клиент, в списке нет, отвечает только тем, у кого есть её ссылка) или isolated (ни в какую сеть не входит, люди со ссылкой подключаются к ней напрямую; для сервера) (по умолчанию "public") |
| `--access-secret` строка | `ECHOFOG_ACCESS_SECRET` | секрет доступа скрытой или изолированной ноды, 22 символа base64url (по умолчанию генерируется при первом запуске и хранится в папке данных); один секрет на нескольких нодах пускает по одной ссылке везде |
| `--access-secret-file` строка | `ECHOFOG_ACCESS_SECRET_FILE` | файл с секретом доступа (например, секрет Docker или Kubernetes); используется, если --access-secret пуст |
| `--data-dir` строка | `ECHOFOG_DATA_DIR` | где лежат база и личность (по умолчанию "/data") |
| `--mnemonic` строка | `ECHOFOG_MNEMONIC` | при первом запуске восстановить эту личность вместо создания новой (лучше --mnemonic-file) |
| `--mnemonic-file` строка | `ECHOFOG_MNEMONIC_FILE` | при первом запуске восстановить личность по фразе из этого файла |
| `--no-create` | `ECHOFOG_NO_CREATE` | не запускаться без личности, а не создавать новую |
| `--password` строка | `ECHOFOG_PASSWORD` | пароль, которым шифруется личность (лучше --password-file; без обоих пароль генерируется и хранится в папке данных) |
| `--password-file` строка | `ECHOFOG_PASSWORD_FILE` | файл с паролем (например, секрет Docker) |
| `--public-addr` строка | `ECHOFOG_PUBLIC_ADDR` | адреса через запятую, которые попадают в ссылку-приглашение (host:port или ws:// URL), когда наблюдаемый адрес не тот, по которому стоит подключаться |
| `--role` строка | `ECHOFOG_ROLE` | client (чаты, звонки, передача файлов и всё остальное) или server (релей или выход на VPS: только сетевые службы; с этой нодой нельзя переписываться и созваниваться, почта для других через неё идёт) (по умолчанию "client") |

### Сеть и транспорты

| Флаг | Переменная окружения | Что делает |
|---|---|---|
| `--advertise-port` число | `ECHOFOG_ADVERTISE_PORT` | публичный порт, по которому пиры достают ноду, если он отличается от порта прослушивания (например, 443, когда проброс публикует порт 443 хоста на эту ноду); 0 — порт прослушивания |
| `--bootstrap` строка | `ECHOFOG_BOOTSTRAP` | host:port/peerid нод для входа в сеть, через запятую (host может быть доменом; по умолчанию — встроенные ноды) |
| `--camouflage-addr` строка | `ECHOFOG_CAMOUFLAGE_ADDR` | host:port, куда отправляются сканеры, которые щупают TCP-порт |
| `--guard-mode` строка | `ECHOFOG_GUARD_MODE` | режим охраны узла пользователя: auto (по умолчанию; включён у не-серверной ноды при --obfs node; приложение ещё и отключает его в стране без цензуры), on или off. Включён: связи через границу несут два-три замаскированных охранных сервера, а не собственная сеть связей ([anti-dpi.ru.md](anti-dpi.ru.md)) |
| `--listen-addr` строка | `ECHOFOG_LISTEN_ADDR` | адрес прослушивания P2P (UDP для QUIC; TCP-обход слушает тот же порт, если не задан --tcp-listen) (по умолчанию ":4242") |
| `--no-hole-punch` | `ECHOFOG_NO_HOLE_PUNCH` | не пробовать прямые соединения между пирами за NAT |
| `--no-port-mapping` | `ECHOFOG_NO_PORT_MAPPING` | не просить роутер пробросить порт (UPnP / NAT-PMP) |
| `--obfs` строка | `ECHOFOG_OBFS` | обфускация UDP: node (по умолчанию; ключи выводятся из peer ID каждой ноды) или off |
| `--obfs-password` строка | `ECHOFOG_OBFS_PASSWORD` | необязательный дополнительный секрет частной сети (обфускация UDP); у всех нод этой сети он должен быть одинаковым |
| `--stealth-password` строка | `ECHOFOG_STEALTH_PASSWORD` | необязательный дополнительный секрет частной сети (маскировка TCP); у всех нод этой сети он должен быть одинаковым |
| `--stun-servers` строка | `ECHOFOG_STUN_SERVERS` | STUN-серверы через запятую (по умолчанию — встроенный список) |
| `--tcp-listen` строка | `ECHOFOG_TCP_LISTEN` | адрес прослушивания TCP-обхода, например :443 (по умолчанию — порт --listen-addr); 'off' выключает его |
| `--tcp-remote-port` число | `ECHOFOG_TCP_REMOTE_PORT` | порт, на который эта нода подключается к другим нодам по TCP-обходу, если он у них на отдельном фиксированном порту (например, 443); 0 — тот же порт, что их QUIC. Не для собственного проброса порта: для него --advertise-port |
| `--tcp-rotate` строка | `ECHOFOG_TCP_ROTATE` | ротация TCP-связей против «заморозки» ТСПУ (связь замолкает примерно после 16 КБ): auto (по умолчанию; через границу из России и там, где связь замерзала), on или off |
| `--tls-cert` строка | `ECHOFOG_TLS_CERT` | PEM-сертификат для --tls-server-name (без него используется самоподписанный) |
| `--tls-key` строка | `ECHOFOG_TLS_KEY` | PEM-ключ для --tls-cert |
| `--tls-server-name` строка | `ECHOFOG_TLS_SERVER_NAME` | домен, который показывает TCP-обход; свой домен — вместе с --tls-cert |
| `--ton-network` строка | `ECHOFOG_TON_NETWORK` | сеть TON для кошелька ноды: testnet или mainnet (по умолчанию testnet) |
| `--transport` строка | `ECHOFOG_TRANSPORT` | auto (QUIC, затем TCP), quic или tcp |
| `--ws-client-ip-header` строка | `ECHOFOG_WS_CLIENT_IP_HEADER` | заголовок, в который CDN перед --ws-listen кладёт адрес клиента (CF-Connecting-IP у Cloudflare), чтобы лимиты считали пиров WebSocket по их собственному адресу; только если слушатель доступен лишь через CDN |
| `--ws-listen` строка | `ECHOFOG_WS_LISTEN` | слушать пиров по WebSocket на этом адресе, чтобы стоять за CDN вроде Cloudflare (например, 127.0.0.1:8080 с CDN перед ним); пусто — выключено |
| `--ws-path` строка | `ECHOFOG_WS_PATH` | HTTP-путь, на котором отвечает WebSocket (по умолчанию /echofog) |

### Релей

| Флаг | Переменная окружения | Что делает |
|---|---|---|
| `--bwprobe-mb-per-min` число | `ECHOFOG_BWPROBE_MB_PER_MIN` | сколько МБ в минуту нода максимум отдаёт на замеры скорости, всем пирам вместе (0 — 48) |
| `--no-bwprobe-serve` | `ECHOFOG_NO_BWPROBE_SERVE` | не отвечать на чужие замеры скорости загрузки (всплески по 12 МБ) |
| `--relay` | `ECHOFOG_RELAY` | ретранслировать звонки и сообщения для пиров, которые не могут связаться напрямую, и хранить сообщения для офлайн-пиров (по умолчанию true) |
| `--relay-allow` строка | `ECHOFOG_RELAY_ALLOW` | peer ID через запятую, которым можно пользоваться релеем, когда он частный |
| `--relay-circuit-mb` число | `ECHOFOG_RELAY_CIRCUIT_MB` | сколько МБ максимум может пройти по одному ретранслируемому соединению (0 — по умолчанию 4096, -1 — без лимита) |
| `--relay-circuits-per-ip` число | `ECHOFOG_RELAY_CIRCUITS_PER_IP` | сколько ретранслируемых соединений максимум у пиров одного IP-адреса; у /24 — вдвое больше (0 — по умолчанию 32, -1 — без лимита) |
| `--relay-circuits-per-peer` число | `ECHOFOG_RELAY_CIRCUITS_PER_PEER` | сколько ретранслируемых соединений максимум у одного пира (0 — по умолчанию 16, -1 — без лимита) |
| `--relay-idle` длительность | `ECHOFOG_RELAY_IDLE` | ретранслируемое соединение, по которому за это время прошло меньше --relay-idle-kb, закрывается (0 — никогда) (по умолчанию 5m0s) |
| `--relay-idle-kb` число | `ECHOFOG_RELAY_IDLE_KB` | см. --relay-idle (0 — по умолчанию 32) |
| `--relay-max-circuits` число | `ECHOFOG_RELAY_MAX_CIRCUITS` | сколько ретранслируемых соединений максимум одновременно (учитывается только положительное число; по умолчанию 200) |
| `--relay-mbps` число | `ECHOFOG_RELAY_MBPS` | скорость всего, что ретранслирует нода, в Мбит/с (0 — без лимита) |
| `--relay-peer-mb-per-day` число | `ECHOFOG_RELAY_PEER_MB_PER_DAY` | сколько МБ в сутки максимум могут пронести ретранслируемые соединения одного пира (0 — по умолчанию 16384, -1 — без лимита) |
| `--relay-peer-mbps` число | `ECHOFOG_RELAY_PEER_MBPS` | скорость ретранслируемых соединений одного пира в Мбит/с (0 — по умолчанию 50, -1 — без лимита) |
| `--relay-private` | `ECHOFOG_RELAY_PRIVATE` | сделать релей частным: он не объявляется и обслуживает только пиров из --relay-allow |
| `--relay-reserved-pct` число | `ECHOFOG_RELAY_RESERVED_PCT` | процент от --relay-max-circuits, оставленный пирам, подключённым 10 минут и дольше (0 — по умолчанию 25, -1 — без резерва) |
| `--relays` строка | `ECHOFOG_RELAYS` | релеи через запятую, к которым подключаться и которые предпочитать, в виде host:port/<peer id> (чтобы добраться до частного релея, куда вам дали доступ) |
| `--signaling` | `ECHOFOG_SIGNALING` | только сигнализация: держать DHT и помогать пирам за NAT соединяться напрямую (пробивка), но не ретранслировать трафик и не хранить сообщения |

### Выход (раздача подключения)

| Флаг | Переменная окружения | Что делает |
|---|---|---|
| `--exit` | `ECHOFOG_EXIT` | раздавать это подключение как выходной узел (публичная нода ещё и публикует его в DHT; скрытая или изолированная обслуживает только тех, у кого есть её ссылка) |
| `--exit-free-gb-per-month` число | `ECHOFOG_EXIT_FREE_GB_PER_MONTH` | на бесплатном выходе — сколько ГБ весь выход раздаёт за календарный месяц (UTC); потом он отказывает в новых соединениях до конца месяца (0 — без лимита) |
| `--exit-free-ip-mb-per-day` число | `ECHOFOG_EXIT_FREE_IP_MB_PER_DAY` | на бесплатном выходе — сколько МБ в сутки (UTC) могут взять все клиенты одного IP-адреса (0 — без лимита) |
| `--exit-free-ip-mbps` число | `ECHOFOG_EXIT_FREE_IP_MBPS` | на бесплатном выходе — скорость всех клиентов одного IP-адреса в Мбит/с (0 — по умолчанию 100, -1 — без лимита) |
| `--exit-free-kb` число | `ECHOFOG_EXIT_FREE_KB` | бесплатный тестовый трафик на клиента в сутки, в КБ (до 1024, действует на платном выходе; там 0 считается как 512) (по умолчанию 512) |
| `--exit-free-mb-per-day` число | `ECHOFOG_EXIT_FREE_MB_PER_DAY` | на бесплатном выходе — сколько МБ в сутки (UTC) может взять один клиент (0 — без лимита) |
| `--exit-free-peer-mbps` число | `ECHOFOG_EXIT_FREE_PEER_MBPS` | на бесплатном выходе — скорость одного клиента в Мбит/с (0 — по умолчанию 50, -1 — без лимита) |
| `--exit-free-peers` строка | `ECHOFOG_EXIT_FREE_PEERS` | peer ID через запятую, которых выход обслуживает бесплатно, без квоты и оплаты (например, ваши устройства); заменяет список, сохранённый в папке данных |
| `--exit-idle` длительность | `ECHOFOG_EXIT_IDLE` | закрывать TCP-соединение через выход, по которому ничего не шло столько времени (0 — никогда) (по умолчанию 5m0s) |
| `--exit-max-lifetime` длительность | `ECHOFOG_EXIT_MAX_LIFETIME` | закрывать TCP-соединение через выход через столько времени, занято оно или нет (0 — никогда) |
| `--exit-max-streams` число | `ECHOFOG_EXIT_MAX_STREAMS` | сколько соединений максимум выход обслуживает одновременно (0 — по умолчанию 4096, -1 — без лимита) |
| `--exit-price` строка | `ECHOFOG_EXIT_PRICE` | цена выхода в долларах за ГБ, оплата в TON или USDT, например 0.05 (0 — бесплатно) (по умолчанию "0") |
| `--exit-streams-per-ip` число | `ECHOFOG_EXIT_STREAMS_PER_IP` | сколько соединений максимум могут держать открытыми клиенты одного IP-адреса (0 — по умолчанию 512, -1 — без лимита) |
| `--exit-streams-per-peer` число | `ECHOFOG_EXIT_STREAMS_PER_PEER` | сколько соединений через выход максимум может держать один клиент (0 — по умолчанию 256, -1 — без лимита) |
| `--exit-udp-per-peer` число | `ECHOFOG_EXIT_UDP_PER_PEER` | сколько UDP-сессий максимум может держать один клиент (0 — по умолчанию 32, -1 — без лимита) |
| `--exit-upload-mbps` число | `ECHOFOG_EXIT_UPLOAD_MBPS` | скорость отдачи, которую объявлять, в Мбит/с (0 — измерить по пирам, для чего они уже должны быть подключены; на сервере задайте её) |
| `--socks5` строка | `ECHOFOG_SOCKS5` | адрес локального SOCKS5-прокси для --use-exit (по умолчанию "127.0.0.1:1080") |
| `--use-exit` строка | `ECHOFOG_USE_EXIT` | пустить локальный SOCKS5-прокси через выход: 'auto', peer ID или ссылка-приглашение (echofog://join?...) |

### API оператора

| Флаг | Переменная окружения | Что делает |
|---|---|---|
| `--api-addr` строка | `ECHOFOG_API_ADDR` | адрес API оператора (пропуска для вашей собственной оплаты или модерации, см. [operator-api.ru.md](operator-api.ru.md)); '' — выключено. Нужен --api-token |
| `--api-token` строка | `ECHOFOG_API_TOKEN` | токен, который требует API оператора ("Authorization: Bearer <token>"), не короче 16 символов; с более коротким API не включится |

### Лимиты на пиров

| Флаг | Переменная окружения | Что делает |
|---|---|---|
| `--max-connections` число | `ECHOFOG_MAX_CONNECTIONS` | к скольким пирам нода подключается сама (учитывается только положительное число; по умолчанию 100) |
| `--max-ids-per-ip` число | `ECHOFOG_MAX_IDS_PER_IP` | сколько разных peer ID максимум может подключиться с одного адреса за 10 минут (0 — по умолчанию 32; -1 — без лимита) |
| `--max-ids-per-subnet` число | `ECHOFOG_MAX_IDS_PER_SUBNET` | то же на /24 или IPv6 /56 (0 — по умолчанию 128; -1 — без лимита) |
| `--max-peers` число | `ECHOFOG_MAX_PEERS` | сколько пиров максимум подключено к ноде по их собственной инициативе (0 — по умолчанию 256, на сервере 2048; -1 — без лимита) |
| `--max-peers-per-ip` число | `ECHOFOG_MAX_PEERS_PER_IP` | сколько пиров максимум одновременно подключено с одного адреса (0 — по умолчанию 16; -1 — без лимита) |
| `--max-peers-per-subnet` число | `ECHOFOG_MAX_PEERS_PER_SUBNET` | сколько пиров максимум одновременно подключено с одной /24 или IPv6 /56 (0 — по умолчанию 64; -1 — без лимита) |

### Статус и логи

| Флаг | Переменная окружения | Что делает |
|---|---|---|
| `--log-level` строка | `ECHOFOG_LOG_LEVEL` | debug, info, warn или error (по умолчанию "info") |

| `--status-addr` строка | `ECHOFOG_STATUS_ADDR` | локальный адрес страницы статуса, которой пользуются "status" и "wallet" ('' — выключить; держите её на loopback) (по умолчанию "127.0.0.1:7070") |
