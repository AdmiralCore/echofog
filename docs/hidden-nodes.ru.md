# Скрытые и изолированные ноды

По умолчанию нода EchoFog **публичная**: она есть в адресной книге сети, а если раздаёт
подключение, выход публикуется, и найти его и пользоваться им по её цене может кто угодно. Иногда
нужно обратное: выход для семьи, команды или платных подписчиков, который посторонние и сканеры
вообще не находят. Для этого есть скрытый и изолированный режимы.

> **Статус: экспериментальный**, как и весь EchoFog. См. [Своя нода](run-a-node.ru.md).

## Три режима

| Режим | Объявление в рынке выходов | Адрес в обмене пирами | Подключение к публичным нодам | Кто может пользоваться |
|---|---|---|---|---|
| **Публичный** (по умолчанию) | да | да | да | все |
| **Скрытый** | нет | нет | да, только как клиент: найти пиров, релей, пробивка NAT | только по ссылке |
| **Изолированный** | нет | нет | нет | только по ссылке, только прямое подключение |

- **Скрытый** подходит для домашнего компьютера или VPS, которому сеть нужна для себя: звонки,
  сообщения, свой VPN. Он ни для кого не работает релеем, не хранит записи DHT за других и не
  сообщает свой порт, поэтому у пиров, с которыми он общается, нет его адреса, чтобы передать
  дальше.
- **Изолированный** подходит для VPS с публичным адресом, который обслуживает только
  приглашённых. Он никуда не подключается сам, даже к bootstrap-нодам, а просто ждёт соединений.
  Ему нужен адрес, до которого можно достучаться: публичный IP или проброшенный порт.

## Ссылка-приглашение

У скрытой и изолированной ноды есть **секрет доступа**. Её ссылка несёт секрет вместе с тем, где
нода находится:

```
echofog://join?v=1&net=echofog&p=101&id=<peer id>&s=<секрет>&a=<host:port>&r=<релей>
```

| Часть | Что значит |
|---|---|
| `v` | формат ссылки. Слишком старое приложение скажет «обновите приложение», а не будет молча не подключаться. |
| `net` | сеть, к которой относится ссылка: `echofog` или имя форка. Приложение скажет «это ссылка другой сети», а не будет пытаться подключиться. Форк задаёт своё имя при сборке: `-ldflags "-X github.com/echofog/echofog-core/internal/config.NetworkName=myfork"`. |
| `p` | версия протокола ноды |
| `id` | peer ID ноды |
| `s` | секрет доступа (только в ссылке скрытой или изолированной ноды) |
| `a` | адрес для прямого подключения (может повторяться) |
| `r` | релей, к которому нода подключена, на случай, если ни один адрес недоступен: приложение подключается к релею и оттуда пробивает NAT (только для скрытых нод; может повторяться) |

В ссылке публичной ноды нет `s`: она только говорит, где нода.

### Что защищает секрет

- Пир доказывает знание секрета **прямо в рукопожатии**, до того как нода скажет хоть слово:
  это HMAC от channel binding TLS-соединения, поэтому доказательство, записанное на одном
  соединении, бесполезно на другом. Кто не смог доказать, не получает ничего, даже публичный ключ
  ноды.
- Запрос на пробивку NAT несёт короткоживущий билет из секрета, поэтому скрытая нода за NAT не
  раскрывает свои адреса посторонним, которые спрашивают через релей.
- Выход проверяет ещё раз: он обслуживает только допущенных, даже по соединениям, которые скрытая
  нода открыла сама (к релеям и нодам DHT). Для всех остальных он выглядит выключенным.

**Ваши контакты** подключаются к скрытой ноде без ссылки, так что звонки и сообщения работают.

### Кто подключился, и новая ссылка

Кто вошёл по ссылке, запоминается (в зашифрованной части базы ноды). **Новая ссылка** меняет
секрет: по старой больше никто новый не войдёт, но те, кто уже подключился, остаются. Чтобы
отключить человека, удалите его из списка: тогда ему понадобится текущая ссылка.

Ссылка даёт **доступ, а не бесплатный трафик**: платят по цене, которую вы задали, как все. Чтобы
кто-то пользовался вашим выходом бесплатно, добавьте его в список бесплатных
(`--exit-free-peers` или **Прокси → Бесплатно для этих людей** в приложении).

## В приложении

**Прокси → Доступ к этому компьютеру**:

- **Публичный / Скрытый** переключает режим. Новый режим заработает после перезапуска приложения.
- **Ваша ссылка-приглашение** (в публичном режиме — **Ваш адрес**) — ссылка, которую вы отдаёте,
  с кнопкой копирования и QR-кодом.
- **Новая ссылка** делает новый секрет; в **Подключились по ссылке** видно, кто вошёл, и каждого
  можно удалить.

Чтобы воспользоваться чужой ссылкой: **Прокси → Конкретная нода**, вставьте ссылку, **Подключить**.

Изолированный режим — для серверов, в приложении его нет.

## На сервере

```bash
echofog-node run --access hidden --exit --exit-price 0.05
```

```bash
echofog-node run --access isolated --exit --exit-price 0.05 --public-addr 203.0.113.5:443
```

| Флаг | Переменная | Что делает |
|---|---|---|
| `--access` | `ECHOFOG_ACCESS` | `public` (по умолчанию), `hidden` или `isolated` |
| `--access-secret` | `ECHOFOG_ACCESS_SECRET` | секрет доступа, 22 символа base64url. Пусто — создаётся при первом запуске и хранится в каталоге данных. Дайте нескольким нодам один секрет, чтобы одна ссылка пускала везде, или держите его в хранилище секретов (Docker или Kubernetes secret). Секрет, заданный здесь, нельзя сменить через `invite --rotate`: меняйте его здесь. |
| `--access-secret-file` | `ECHOFOG_ACCESS_SECRET_FILE` | читать секрет из файла (Docker или Kubernetes secret), если `--access-secret` пуст |
| `--public-addr` | `ECHOFOG_PUBLIC_ADDR` | адреса для ссылки (`host:port` или `ws://` URL через запятую), когда наблюдаемый адрес не тот, по которому надо подключаться: домен, проброс порта |

Скрытой и изолированной ноде не нужен `--exit-upload-mbps`: она не объявляет скорость.

Ссылку и список подключившихся отдаёт запущенная нода:

```bash
echofog-node invite             # показать ссылку
echofog-node invite --list      # кто вошёл по ней
echofog-node invite --rotate    # новый секрет: по старой ссылке никто новый не войдёт
echofog-node invite --remove <peer id>
echofog-node invite --new-secret  # новый секрет для --access-secret; нода не нужна
```

В ссылку идёт адрес, который нода видит снаружи, с портом `--advertise-port`, если он задан
(Docker публикует порт 443 хоста на 4242 контейнера). В Docker команды запускаются внутри
контейнера: `docker compose -f deploy/docker-compose.yml exec node echofog-node invite`. Пошагово
для Docker — в [VPS через Docker](deploy-vps.ru.md#выход-только-для-приглашённых).

Команды идут через локальный status-эндпоинт (`--status-addr`, по умолчанию loopback), поэтому
работают только на той машине, где запущена нода.

Чтобы пользоваться скрытым выходом с другого сервера: `echofog-node run --use-exit '<ссылка>'`
(кавычки нужны, чтобы оболочка не разбирала `&`).

## Ограничения

- Старые версии приложения не знают об этих режимах: они не читают ссылки-приглашения, и скрытая
  нода их не пускает.
- Без обфускации (`--obfs off`) TLS-сертификат QUIC содержит публичный ключ ноды, и сканер,
  прошедший TLS-рукопожатие, узнаёт peer ID ноды по этому адресу, хотя дальше всё равно не
  продвинется. Не выключайте обфускацию (она включена по умолчанию).
- Скрытая нода за NAT доступна только через релеи, указанные в её ссылке. Если она перешла на
  другие релеи, выдайте свежую ссылку.
- Смена режима требует перезапуска.
- Как любая нода, скрытая отвечает на запросы обмена пирами и DHT от тех, с кем соединена, и
  называет публичные адреса известных ей пиров; среди них могут быть те, кто ею пользуется. Её
  собственного адреса в этих ответах нет никогда.
