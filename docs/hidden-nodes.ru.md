# Доступ только для своих: скрытые и изолированные ноды

Это руководство для тех, кто хочет раздавать подключение **только определённым людям**: семье,
друзьям, команде или клиентам, которые платят вам напрямую. Разбираться в технике не нужно: сначала
каждый режим объяснён простыми словами, потом идут пошаговые инструкции. Технические подробности —
в самом конце, для тех, кому интересно.

> **Статус: экспериментальный**, как и весь EchoFog. См. [Своя нода](run-a-node.ru.md).

## Коротко

Обычно, когда вы раздаёте подключение в EchoFog, ваш компьютер похож на магазин на оживлённой
улице: он есть на карте, его может найти любой и зайти (и заплатить вашу цену).

Иногда нужно обратное: дверь без вывески, которая открывается только тем, у кого есть ключ. Именно
это делают **скрытый** и **изолированный** режимы.

- Вы переключаете компьютер (или сервер) в один из этих режимов.
- Он выдаёт вам **ссылку-приглашение**. Ссылка — это ключ.
- Вы отправляете ссылку тем, кому хотите. Подключиться смогут только они. Все остальные, включая
  сканеры, которые прочёсывают интернет в поисках VPN-серверов, не получают никакого ответа: для них
  там как будто ничего нет.

## Слова, которые здесь встречаются

| Слово | Что значит |
|---|---|
| **Нода** | Компьютер, на котором работает EchoFog: ваше приложение или программа `echofog-node` на сервере. |
| **Выход** | Нода, которая раздаёт своё подключение к интернету. Ваш трафик выходит в интернет через неё, поэтому сайты видят адрес выхода, а не ваш. |
| **Ссылка-приглашение** | Строка, которая начинается с `echofog://join?`. Она говорит приложению, где ваша нода, и несёт ключ, который пускает внутрь. |
| **Секрет** | Ключ внутри ссылки. У кого есть ссылка, у того есть и секрет, поэтому обращайтесь со ссылкой как с ключом от квартиры. |
| **Контакт** | Человек из вашего списка чатов в приложении. |
| **Релей** | Другая нода сети, которая помогает двум компьютерам найти друг друга, когда напрямую они соединиться не могут. |
| **За роутером (NAT)** | Большинство домашних и мобильных подключений: у компьютера нет своего адреса в интернете, и подключиться к нему напрямую без помощи нельзя. |
| **VPS** | Арендованный сервер в дата-центре со своим публичным адресом. |

## Три режима

### Публичный (по умолчанию)

**Что видят другие:** ваша нода есть в сети. Если вы раздаёте подключение, ваш выход появляется в
списке выходов у всех, с вашей ценой.

**Кто может пользоваться выходом:** любой, по вашей цене. Люди из списка *Бесплатно для этих людей*
пользуются бесплатно.

**Когда выбирать:** если хотите зарабатывать на незнакомых людях или помочь как можно большему
числу людей.

### Скрытый

**Что видят другие:** ничего. Ваша нода не значится ни в каких списках, не помогает чужим (не
работает ни для кого релеем) и никогда не сообщает другим нодам свой адрес. Если кто-то знает её
адрес и пытается подключиться без ссылки, нода не отвечает.

**Что работает у вас:** всё. Нода по-прежнему пользуется сетью как обычно: чаты, звонки, ваш
собственный VPN, поиск других людей. Просто при этом она остаётся невидимой.

**Кто может пользоваться выходом:** только те, у кого есть ваша ссылка, плюс ваши контакты (чтобы
друзья из списка чатов могли вам звонить и писать), плюс те, кто уже входил по прежней ссылке.

**Работает ли за домашним роутером:** да. В ссылке указаны один-два релея, к которым подключена
нода; если напрямую соединиться нельзя, приложение другого человека доберётся до вас через них.

**Когда выбирать:** если раздаёте с домашнего компьютера или ноутбука, или с сервера, на котором
нельзя открыть порт, и хотите, чтобы пользовались только свои.

### Изолированный

**Что видят другие:** совсем ничего. Изолированная нода даже не входит в сеть: она никуда не
подключается сама ни к одной ноде EchoFog, даже к входным точкам сети. Она просто ждёт. (Публичные
STUN-серверы и ваш роутер она всё же спрашивает, какой у неё внешний адрес, чтобы вписать его в
ссылку.)

**Что работает:** только подключения тех, у кого есть ссылка, и только **напрямую**. Релеев в её
ссылке нет, поэтому до неё должно быть можно достучаться из интернета: нужен VPS с публичным
адресом и открытым портом.

**Когда выбирать:** если у вас есть VPS и нужен частный выход для своих людей, и больше ничего. Это
самый закрытый режим и обычный выбор для сервера.

### Сравнение

| | Публичный | Скрытый | Изолированный |
|---|---|---|---|
| Виден в списке выходов | да | нет | нет |
| Другие ноды узнают его адрес | да | нет | нет |
| Помогает чужим как релей | да (если релей включён) | нет | нет |
| Сам пользуется сетью (чаты, звонки, свой VPN) | да | да | нет |
| Кто может пользоваться выходом | все | владельцы ссылки, контакты, уже входившие | владельцы ссылки и уже входившие |
| Работает за домашним роутером | пользоваться — да; обслуживать других — нужен открытый порт | да, через релеи | нет, нужен публичный адрес |
| Где включается | приложение или сервер | приложение или сервер | только сервер |

### Какой выбрать?

- Раздаю **с домашнего компьютера или ноутбука**, только семье и друзьям → **Скрытый**.
- У меня **VPS**, хочу **частный VPN** для своих людей или клиентов → **Изолированный**.
- У меня VPS, но **порт открыть нельзя** (или он за чужим роутером) → **Скрытый**.
- Хочу, чтобы мой выход **мог найти и оплатить любой** → **Публичный**.

## Пошагово: раздавать с домашнего компьютера только своим (приложение)

1. Откройте в приложении **Прокси** и прокрутите вниз до карточки **Доступ к этому компьютеру**.
2. Выберите **Скрытый**. Карточка предупредит, что новый режим заработает после перезапуска.
3. **Полностью закройте приложение и откройте снова.** Теперь у карточки есть пометка *скрытый*.
4. В **Раздаче подключения** задайте цену (`0` — бесплатно для всех, у кого есть ссылка) и нажмите
   **Начать раздачу**. Скрытому выходу скорость отдачи не нужна: её можно оставить равной 0.
   Карточка теперь пишет, что раздача не публикуется.
5. В **Доступ к этому компьютеру → Ваша ссылка-приглашение** нажмите кнопку копирования (или
   кнопку QR-кода) и отправьте ссылку своим людям через мессенджер, которому доверяете.

Если карточка пишет *Компьютер пока не знает адреса, по которому до него можно достучаться*,
подождите минуту, пока приложение подключится к сети.

**Помните:** пока раздача включена, трафик приглашённых выходит в интернет с **вашего** адреса.
Прочтите [Что будет, если я раздам своё подключение?](faq.ru.md#что-будет-если-я-раздам-своё-подключение).

## Пошагово: подключиться по ссылке, которую вам дали (приложение)

1. Скопируйте присланную ссылку (она начинается с `echofog://join?`).
2. В приложении откройте **Прокси → Конкретная нода** и вставьте ссылку в поле.
3. Под полем приложение покажет, что это за ссылка: *Приглашение на скрытый компьютер* и начало его
   ID. Если что-то не так, оно скажет, что именно (см. [Проблемы](#проблемы-и-что-делать)).
4. Нажмите **Подключить**.

Приложение запоминает ключ. В следующий раз нажмите **Подключиться к последнему выходу** или
выберите выход в списке **Ваши выходы**: вставлять ссылку заново не нужно. Если владелец потом сделает
новую ссылку, вы останетесь с доступом.

Оплата — как у любого выхода: если владелец задал цену, экран Прокси покажет, как заплатить.

## Пошагово: частный выход на VPS через Docker (изолированный)

Самый частый вариант. Предполагается, что вы прошли [VPS через Docker](deploy-vps.ru.md) до шага 3:
Docker установлен, порт открыт (UDP и TCP 443), файл `deploy/.env` есть.

1. Откройте файл настроек:

   ```bash
   nano deploy/.env
   ```

2. Задайте эти строки (цену поставьте свою):

   ```bash
   ECHOFOG_ACCESS=isolated
   ECHOFOG_EXIT=true
   ECHOFOG_EXIT_PRICE=0.05        # долларов за ГБ; 0 — бесплатно для всех, у кого есть ссылка
   ECHOFOG_ADVERTISE_PORT=443     # уже есть в файле: порт, к которому подключаются люди
   ```

   С `isolated` не нужны `ECHOFOG_BOOTSTRAP`, `ECHOFOG_RELAY` и `ECHOFOG_EXIT_UPLOAD_MBPS`: они
   не учитываются.

3. Запустите (или перезапустите) ноду:

   ```bash
   docker compose -f deploy/docker-compose.yml up -d --build
   ```

4. Возьмите ссылку:

   ```bash
   docker compose -f deploy/docker-compose.yml exec node echofog-node invite
   ```

   Команда выведет одну строку, начинающуюся с `echofog://join?`. Это и есть ссылка, которую вы
   раздаёте. Нода также пишет её в лог при запуске (`Invite link:`).

   Тем, у кого в сети заблокирован UDP, нужен TCP-обход, а в Docker он выключен, пока вы не укажете
   настоящий сайт, под который нода будет маскироваться (`ECHOFOG_TLS_SERVER_NAME`,
   `ECHOFOG_CAMOUFLAGE_ADDR`): см. [TCP-обход](deploy-vps.ru.md#tcp-обход). Большинству хватает и
   одного UDP.

5. Проверьте со своего компьютера: вставьте ссылку в **Прокси → Конкретная нода** и подключитесь.
   Потом посмотрите на сервере, кто вошёл:

   ```bash
   docker compose -f deploy/docker-compose.yml exec node echofog-node invite --list
   ```

В ссылку идёт публичный IP сервера (нода узнаёт его сама) с портом из `ECHOFOG_ADVERTISE_PORT`.
Если хотите, чтобы в ссылке было **доменное имя** (удобно, если IP может смениться), или у сервера
несколько адресов, добавьте:

```bash
ECHOFOG_PUBLIC_ADDR=vpn.example.org:443
```

Ключ создаётся при первом запуске и хранится в томе `echofog-data` вместе с личностью ноды. Он
переживает перезапуски и обновления: ссылка остаётся прежней, пока вы не сделаете новую.

## Пошагово: скрытая нода через Docker

То же самое, но с `ECHOFOG_ACCESS=hidden`. Подходит, если до сервера нельзя достучаться из
интернета (порт не открыть или он за роутером): нода держит соединение с парой релеев и указывает их
в ссылке. `ECHOFOG_BOOTSTRAP` оставьте как есть: скрытой ноде сеть нужна.

Если релеи из ссылки пропадут, до скрытой ноды без открытого порта будет не достучаться. Время от
времени запускайте `invite` и, если ссылка изменилась, раздайте свежую.

## Пошагово: без Docker

```bash
echofog-node run --access isolated --exit --exit-price 0.05 --advertise-port 443
```

и в другом терминале на том же сервере:

```bash
echofog-node invite
```

У каждой настройки есть флаг и переменная окружения, см. таблицу в
[Технических подробностях](#технические-подробности).

## Как управлять доступом

Всё это есть в карточке **Доступ к этому компьютеру** в приложении или в команде `invite` на
сервере (в Docker добавьте впереди `docker compose -f deploy/docker-compose.yml exec node`).

| Хочу… | В приложении | На сервере |
|---|---|---|
| Снова увидеть ссылку | *Ваша ссылка-приглашение* | `echofog-node invite` |
| Посмотреть, кто вошёл | *Подключились по ссылке* | `echofog-node invite --list` |
| Чтобы по ссылке больше не входили новые люди | **Новая ссылка** | `echofog-node invite --rotate` |
| Отключить одного человека | кнопка корзины рядом с ним | `echofog-node invite --remove <его peer ID>` |

Как это работает, простыми словами:

- **Все, кто вошёл по ссылке, запоминаются.** Они могут переподключаться когда угодно без ссылки,
  даже после перезапуска.
- **Новая ссылка** меняет ключ. Тот, у кого **старая** ссылка, больше не может войти **впервые**. Те,
  кто уже вошёл, остаются. Это то, что нужно сделать, если ссылка утекла.
- **Удаление человека** стирает его из памяти. Чтобы вернуться, ему понадобится **текущая** ссылка.
- То есть, чтобы выгнать кого-то после утечки ссылки: сделайте новую ссылку, удалите этого человека и
  отправьте новую ссылку тем, кого хотите оставить.
- **Ваши контакты** входят без всякой ссылки (чтобы могли вам звонить) и в списке не показываются.

## Деньги: ссылка — это доступ, а не бесплатный трафик

Ссылка пускает людей **внутрь**. Платят они по цене, которую вы задали, как на любом выходе; если
выход платный, первые немного пробного трафика в день бесплатны. Чтобы кто-то пользовался вашим
выходом **бесплатно**, добавьте его в **Бесплатно для этих людей** в приложении (на сервере —
`ECHOFOG_EXIT_FREE_PEERS`). Чтобы было бесплатно для всех, у кого есть ссылка, поставьте цену 0.

## Как беречь ссылку

- **Любой, у кого есть ссылка, может пользоваться вашим выходом.** Отправляйте её только тем, кому
  доверяете, в личной переписке. Не публикуйте её открыто.
- Если ссылка утекла, сделайте **новую ссылку** (см. выше).
- В ссылке нет вашего пароля, фразы восстановления или кошелька. Она только открывает дверь к ноде.
- На сервере команда `invite` работает только на самом сервере: через интернет ссылку у ноды не
  спросить.

### Что на самом деле защищает ключ

- Посторонний, который знает ваш адрес, но не знает ключа, **не получает ответа**: ни отказа, ни ID
  ноды, ничего. Сканеры, ищущие VPN-серверы, видят молчащий UDP-порт, а на TCP-порту — обычный
  сайт, под который маскируется нода (см. [Anti-DPI](anti-dpi.ru.md)).
- Человек с ключом доказывает, что знает его, **не отправляя сам ключ**, и доказательство годится
  только для одного соединения: тот, кто записывает трафик, не сможет его повторить.
- Даже когда скрытая нода сама подключается к другим нодам (например, к релеям), они не могут
  пользоваться её выходом: для них он выглядит выключенным.

## Несколько серверов по одной ссылке

Можно дать нескольким серверам **один и тот же ключ**, и тогда одна ссылка работает для всех (адрес в
ссылке у каждого сервера свой). Сделайте ключ один раз:

```bash
docker compose -f deploy/docker-compose.yml run --rm node invite --new-secret
```

Команда выведет 22 символа. Пропишите их на каждом сервере в `deploy/.env`:

```bash
ECHOFOG_ACCESS_SECRET=<эти 22 символа>
```

Или, чтобы не держать его в файле настроек, как Docker secret: сохраните в
`deploy/echofog_access_secret.txt`, раскомментируйте строки `echofog_access_secret` в
`deploy/docker-compose.yml` и задайте
`ECHOFOG_ACCESS_SECRET_FILE=/run/secrets/echofog_access_secret`. Секреты Kubernetes работают так
же, через файл.

Ключ, заданный так, нельзя сменить командой `invite --rotate` или кнопкой **Новая ссылка**: меняйте
его в настройках и перезапускайте ноды.

## Проблемы и что делать

| Что вы видите | Что это значит | Что делать |
|---|---|---|
| *Эту ссылку сделала более новая версия EchoFog* | У того, кто сделал ссылку, приложение новее. | Обновите приложение. |
| *Это ссылка другой сети (…)* | Ссылка от другой сети на основе EchoFog (форка). | Попросите ссылку для этой сети или используйте приложение той сети. |
| *Это не ссылка-приглашение…* | Часть ссылки потерялась, часто её обрезает мессенджер. | Попросите прислать снова, например файлом или QR-кодом. |
| *Компьютер пока не знает адреса, по которому до него можно достучаться* / `no link yet` | Нода ещё не знает свой публичный адрес. | Подождите минуту. На сервере задайте `ECHOFOG_PUBLIC_ADDR`. |
| *Could not reach the node* (не удалось достучаться) | Адрес из ссылки не отвечает. | Изолированная: проверьте, что сервер работает и UDP (и TCP) 443 открыты в файрволе и в панели провайдера. Скрытая: попросите свежую ссылку, могли смениться релеи. |
| Переключил на Скрытый, но ничего не изменилось | Режим меняется только после перезапуска. | Полностью закройте приложение и откройте снова. |
| Друзья не могут мне позвонить, с тех пор как я скрыт | Должны смочь, если они у вас в контактах. | Проверьте, что они есть в списке чатов. |
| Раньше люди входили, теперь не могут | Их кто-то удалил, или данные ноды пропали (новая личность). | Отправьте им текущую ссылку. |

## Ограничения

- **Старые версии приложения** не знают об этих режимах: они не читают ссылки-приглашения, и скрытая
  нода их не пускает.
- **Смена режима требует перезапуска.** Изолированный режим — только для серверов; в приложении есть
  Публичный и Скрытый.
- **Не выключайте обфускацию** (она включена по умолчанию). С `--obfs off` сканер, прошедший
  зашифрованное рукопожатие с вашим портом, может узнать ID ноды, хотя дальше всё равно не
  продвинется.
- **Скрытая нода за роутером** доступна только через релеи, указанные в её ссылке. Если она перешла
  на другие релеи, раздайте свежую ссылку.
- Как любая нода, скрытая отвечает другим нодам на вопросы **о том, кто ещё есть в сети**, и может
  назвать публичные адреса известных ей нод, в том числе тех, кто ею пользуется. Её собственного
  адреса в этих ответах нет никогда.

## Технические подробности

### Ссылка

```
echofog://join?v=1&net=echofog&p=101&id=<peer id>&s=<секрет>&a=<host:port>&r=<host:port/id релея>
```

| Часть | Что значит |
|---|---|
| `v` | Формат ссылки. Приложение, которое не может его прочитать, говорит «обновите приложение», а не молча не подключается. |
| `net` | Сеть: `echofog` или имя форка, которое задаётся при сборке: `-ldflags "-X github.com/echofog/echofog-core/internal/config.NetworkName=myfork"`. Ссылка другой сети отклоняется с понятным сообщением. |
| `p` | Версия протокола ноды. |
| `id` | Peer ID ноды. |
| `s` | Секрет доступа, 16 байт в base64url. Только в ссылке скрытой или изолированной ноды; в ссылке публичной ноды его нет, она только говорит, где нода. |
| `a` | Адрес для подключения, `host:port` или `ws://` URL. Может повторяться. |
| `r` | Релей, к которому подключена нода, `host:port/<peer id релея>`, для пробивки NAT, если ни один адрес не отвечает. Только у скрытых нод. Может повторяться. |

### Как проверяется доступ

- Инициатор отправляет HMAC-SHA256 секрета от channel binding TLS-соединения, своего nonce и своего
  публичного ключа прямо в первом сообщении рукопожатия. Скрытая нода проверяет его, ещё ничего не
  отправив, поэтому пир без него не узнаёт ничего, даже публичного ключа ноды.
- Запрос на пробивку NAT несёт билет: HMAC секрета от peer ID запрашивающего и текущей минуты
  (±2 минуты). Без него скрытая нода не отвечает и никому не раскрывает свои адреса.
- Выход тоже проверяет доступ на каждом туннеле, в том числе по соединениям, которые скрытая нода
  открыла сама.
- Секрет, список вошедших и секреты нод, куда пригласили эту ноду, хранятся в зашифрованной части
  базы ноды. В списке вошедших не больше 10 000 пиров.

### Настройки сервера

| Флаг | Переменная | Что делает |
|---|---|---|
| `--access` | `ECHOFOG_ACCESS` | `public` (по умолчанию), `hidden` или `isolated`. Скрытый и изолированный выключают релей. |
| `--access-secret` | `ECHOFOG_ACCESS_SECRET` | Секрет, 22 символа base64url. Пусто — создаётся при первом запуске и хранится в каталоге данных. |
| `--access-secret-file` | `ECHOFOG_ACCESS_SECRET_FILE` | Читать секрет из файла (Docker или Kubernetes secret), если `--access-secret` пуст. |
| `--public-addr` | `ECHOFOG_PUBLIC_ADDR` | Адреса для ссылки через запятую, `host:port` или `ws://` URL, вместо наблюдаемого. |
| `--advertise-port` | `ECHOFOG_ADVERTISE_PORT` | Если задан, в ссылку идёт наблюдаемый IP с этим портом (Docker публикует порт 443 хоста на 4242 контейнера). |
| `--use-exit` | `ECHOFOG_USE_EXIT` | Принимает и ссылку-приглашение, чтобы пользоваться скрытым выходом с сервера. Берите в кавычки: `--use-exit '<ссылка>'`. |

`echofog-node invite` выводит ссылку; `--list`, `--rotate`, `--remove <peer id>` управляют
доступом; `--new-secret` выводит новый секрет без запущенной ноды. Команды обращаются к локальному
status-эндпоинту ноды (`--status-addr`, по умолчанию loopback), поэтому работают только на той
машине, где запущена нода, а команды, которые что-то меняют, требуют заголовка, который веб-страница
отправить не может.
